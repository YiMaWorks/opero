# code/web：Opero 网页端

> **2026-11-23 起同一份打包有两种用法**：官网和 `/demo` 用假数据（`src/data/mock.ts`）；装好的一套由 `code/server` 发出去，在 `index.html` 里注入 `window.OPERO_MODE='instance'`（`src/mode.ts` 的 `LIVE`），数据从后台来（`src/live.ts`：开机拉 `/api/bootstrap`、SSE 收变化），`src/store.ts` 的动作在 LIVE 下调接口；真的一套专用的页面在 `src/pages/live.tsx`，还没做的页面显示「还在做」。下面是原型时期的说明。

> 2026-11-22 起是**个人开发助理，一人一套**：只有主人一个账号，没有用户、授权和申请。
> 0.7.0 起**样式照 KidLock 聊天样式**（`docs/规范/表单与卡片.md` 第 7 节），并且能放进安卓 App 外壳里跑（`src/native.ts`，`docs/规范/App外壳.md`）。

**所有看得见的功能都能点**，数据是假的（`src/data/mock.ts`），没接后台和 AI 员工。用来一次看全界面、定下每个入口放哪；后台照着这些页面和 `src/store.ts` 的动作做接口。

## 结构（正式版沿用）

| 位置 | 是什么 |
|---|---|
| `src/types.ts` | 所有数据结构：消息 / 卡片（= `docs/规范/表单与卡片.md`）、员工、工作空间、问题、服务器、发布、凭证、数据源、触发器、插件、操作记录、用量、设置 |
| `src/store.ts` | **数据仓库**：页面只从这里读（`useStore`）、只调这里的动作。现在初始数据来自 `data/mock.ts`；接后台时：初始数据改成调接口、消息改成服务器推送、动作改成调接口——**页面不用改** |
| `src/data/mock.ts` | 演示数据（接后台后删） |
| `src/pages/` | 页面：`people`（员工）、`workspace`（工作空间 / 问题）、`apps`（服务器、发布、凭证、数据、触发器、插件、审计）、`me`（用量、设置、安全、关于）、`auth`（登录、开机向导）、`panels`（看改动、查询结果）；`index.tsx` 是路由表 + 员工底部菜单 → 页面 |
| `src/pages/nav.ts` | 页面拿到的导航（进下一页 / 返回 / 关面板 / 打开某员工的聊天）；同一个页面可放在页签里，也可放在聊天右侧面板里 |
| `src/components/` | `Chat`、`SessionList`、`cards`（7 种内核卡片）、`ui`（通用小组件）、`overlays`（搜索、找员工聊、验证本人、提示）、`brand`（标志、启动动画）、`Markdown`（AI 回复一律用它显示）、`ErrorBoundary`（页面出错兜底、发版后自动刷新） |
| `src/native.ts` | 在 Opero App 里时和外壳打交道（指纹验证本人、状态栏颜色、点通知打开会话、这台手机的设置）；浏览器里什么都不做 |
| `src/work.ts` | work 设置的选项：各执行器的模型、思考方式、审核方式 |
| `src/menus.ts` | 员工底部菜单注册表（二开入口，见 `docs/规范/底部菜单.md`） |
| `src/App.tsx` | 外壳：登录 → 开机向导 → 主界面；每个页签一摞页面；聊天面板；侧滑返回一层层关；深浅色主题 |
| `src/styles.css` | 设计系统：颜色全是变量，深色主题只换变量；≤ 860px 手机布局 |

## 怎么看（建议顺序）

1. 打开 → 启动动画 → **登录**（演示账号已填好）→ **开机向导**（7 步：账号、接服务器、接 AI 执行器、**带入你的权限**、拉代码、系统管家、后台开发员工；也可「跳过」）。
2. **会话**（像微信）：置顶 / 免打扰（长按或右键）、红字 `[要你确认]`；右上角 🔍 搜索（员工、聊天记录、项目、问题）、＋ 找员工聊。
3. 「mov 日志值班」→ 问题卡片「修复」→ 14 秒主线（期间底部有「停止」）→「看改动」→「撤销合并」；底部菜单「问题清单 / 日志扫描 / 查生产库 / 发布记录」打开的都是真页面。
4. **work 设置**：手机点聊天顶栏的「Opus 5.5 · 思考高 · 自动」（电脑在输入框下面），改模型 / 思考方式 / 审核方式，刷新后还在；「···」里有新话题、压缩上下文、重启 work；员工干活时发消息 = 插话。
5. 「mov 开发」指纹确认、「uugo 开发」提问卡片、聊天里 ＋ 发图片 / 文件，手机上按住说话（上滑取消）。
6. **员工**：档案（用量、授权、触发器、记忆）、新建 / 编辑。**工作空间**：项目详情（分支、提交、问题、文档、预览）、接入仓库、问题清单。
7. **应用**（电脑在左边导航，手机在「我」里）：服务器（监控、只读命令、接入）、发布（记录、应用和环境、AI 发版设置、回滚）、凭证（看明文要指纹）、数据（查询台、库表结构、写操作快照）、触发器、插件、操作记录（你刚才点的都记在这）。
8. **我**：**我的习惯**（所有员工都遵守的个人规矩）、**定制和二开**（你的 fork、官方新版一键交给后台开发合并 → 预览 → 上线、你做过的改动、扩展点）、用量和成本、设置（生产保护、通知、**深色主题**、语言）、账号安全、关于、退出登录、重走开机向导。
10. **底座能力**：会话「消息助理」（汇总；每条「去回复」到原处自己回、「给我个回复建议」可选语言复制、「不关我事」、转给后台开发；**默认不起草不代发**）、应用 →「消息渠道」、底部菜单「收件箱」；聊天「···」→「换一个 work」「聊天设置」（头像 / 名字 / 背景 / 提醒）；员工档案的记忆仓库、work 历史、「搬到另一台服务器」；红点只给要你决定的（其它是灰点）。
11. **底座能力（二）**：应用 →「知识库」「流程」（跑一次）、「服务器和电脑」→ 接入机器可选「我的电脑」；聊天「···」→「把刚才做的存成流程」；员工列表「从模板建」、员工档案「导出成模板」「常用流程」；我 → 用量和成本 →「每月预算」；设置 →「AI 用不了时」（备用执行器 + 模拟 AI 不可用，聊天顶部会出提示条）。
9. **权限和凭证**（应用里）：按服务器 / 数据库 / 代码仓库 / 云账号 / AI 分组，每个账号写清「能做什么」和哪些员工在用；员工档案里能看到它「用到的权限」。编辑员工时底部菜单改成点选。

## 构建

`npm run build`（云效流水线 `deploy/build-web.sh` 执行）。类型检查 `npm run typecheck`。本地开发 `npm i && npm run dev`。

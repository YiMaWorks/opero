# opero 变更记录（最新在最上面）

## server 0.25.0 + web 0.41.0（2026-11-25）：一个项目多个编译组件
- 一个项目可以有好几个编译组件（比如网页、安卓、后台），每个有自己的模板、在哪编、打包工具和流水线，各自试编译（可以同时编）。
- 发布目标选「发哪个编译组件」，也可以选「不编译」只跑部署命令。
- 流水线按组件区分，不会互相覆盖：云效每个组件一条流水线；GitHub 每个组件一个工作流文件；GitLab 一个文件里每个组件一个任务；Jenkins 每个组件一个任务。
- 员工的编译工具都带上组件（加、改、删、生成流水线、试编、看结果），发布目标工具能选组件。
- 以前项目上的那份编译设置自动变成第一个组件，流水线和发布目标照用。

## server 0.24.6（2026-11-25）：每个端都能自己登录
- 原生 App / 桌面端可以直接用账号密码登录（`POST /api/app/login`，开了两步验证再 `POST /api/app/login/mfa`），不用先在网页上拿配对码；配对码登录保留为可选。几个端、几台设备可以同时登着。
- 改密码会把所有设备一起断开（以前只清了登录会话，App 能用设备令牌悄悄换个新的）。

## server 0.24.5 + web 0.40.8（2026-11-25）：给原生 App 用
- 原生 App 的会话令牌和 App 里嵌的网页不再互相踢下线（两种会话各记各的；断开设备、改密码照旧都清）。
- 网页嵌入模式：`/api/app/ticket` 带 `embed: true`，打开后只显示那一页；JS 桥加 `OperoNative.open(route)`、`OperoNative.close()`、`__operoNative.back()`。
- 每张卡片都保证有标题，各端不认识的卡片按通用样子显示。
- 接口文档：新增 `docs/api/卡片.md`；`docs/api/README.md` 补了两种会话、嵌网页、卡片按钮的请求和返回、文件地址。

## server 0.24.4（2026-11-25）：多端架构
- 代码按端分：`code/server`（接口）、`web`、`android`、`apple`（iPhone / iPad / Mac，SwiftUI）、`windows`（WinUI 3）、`desktop`（Electron 过渡版）。见 `docs/多端架构.md`。
- 接口文档：`docs/api/README.md`（约定、登录、实时推送、核心流程）和自动生成的 `docs/api/接口清单.md`（`node code/server/scripts/api-list.mjs`）。
- 原生 App 登录：`POST /api/app/session` 用设备令牌换会话令牌，主人的接口认 `Authorization: Bearer`（网页照旧用 cookie）。
- `OPERO_WEB=none`：后台只提供接口，不托管网页。

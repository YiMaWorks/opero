# opero 变更记录（最新在最上面）

## server 0.10.0 + web 0.23.0（2026-11-24）
- 编译照云效那套：每个工作空间一份编译设置（Node / Go / 安卓 / Java Spring / 自定义命令，产物放 out/，带 SHA256SUMS / VERSION / COMMIT），在云效流水线、GitHub Actions 或自己的服务器上编；云效和 GitHub 能一键生成流水线。
- 发布：编好的包核对 SHA256 后发到环境的每台服务器（可以多台），包里的 deploy.sh 自己装（部署目录在 OPERO_DIR，也认 KL_DIR，以前给云效写的部署脚本能直接用）；失败自动回滚、留几个版本能一键回滚。
- 服务器能登记本地目录：员工只读、员工能改、发布能部署进去；Agent 自动用 ACL 给 AI 用户开权限，去掉就收回。部署目录必须登记过才能发。

## server 0.9.0 + web 0.22.0 + android 0.2.0（2026-11-24）
- 发布系统：每个工作空间的发布目标可以先编译（任意一台服务器）、给 apk / aab 签名、发到目标服务器、发完检查地址；失败自动退回上一个版本，留最近几个版本能一键回滚。网页「应用 → 发布」看记录和每一步的输出。
- 员工发布：每个目标设员工能不能发（直接发 / 发前问你 / 不许）；直接发的失败了，原因自动发回给员工接着修（3 小时内最多 3 次）。
- 合并请求：员工可以在自己的分支上改，干完提合并请求（GitHub、GitLab、Gitee、Codeup），聊天里能刷新状态。
- 签名证书：上传 keystore 和密码（加密存），发布和员工签名都用，密码员工拿不到。
- 域名：登记 Cloudflare / 阿里云的域名，开给员工改解析；网页上也能直接加改删。
- 消息助理：接上邮箱（IMAP）和 Slack，AI 分「要你看 / 知道就行 / 不重要」并写摘要，你的规则优先；要的话写回复建议（用对方的语言 + 中文意思），只写不发。网页「收件箱」「消息渠道」。
- 提醒发到外面：Telegram、Slack、企业微信、钉钉、飞书、邮件、Webhook；按渠道选发「要你决定的 / 出错的 / 全部」，失败自动重试，能「试一下」。
- 通行密钥：用指纹 / 面容登录（不用密码），也能用来验证本人。
- 两步验证：密码登录后再输验证器 App 的动态码；10 个恢复码。
- 说话转文字：聊天输入框旁的话筒，App 里用手机自带的语音识别，浏览器里用 Chrome / Edge / Safari 的。
- 服务器详情能看日志：选服务或日志文件，关键字过滤，错误标红，能自动刷新。
- 安卓外壳 0.2.0：外壳自己的文字跟手机系统语言（7 种）；语音输入。
- 桌面端 0.1.0（新）：托盘显示等你处理的数量、系统通知点了直达、关窗口留在托盘；和手机一样用配对码连接。

## server 0.7.0 + web 0.20.0（2026-11-24）
- 员工记忆仓库：每个员工一个自己的 git 仓库（角色、人设、交接、每月记录、机器笔记），每轮干完自动提交；可以配远端，换服务器时没配远端也会把仓库搬过去。员工档案里能打开、能改。
- 工作空间自动 git：开工前拉到最新（冲突告诉员工先解决），干完自动提交推送（没做完的标「[未完成]」，你停下的不提交），推送被拒变基一次再推；工作空间里能关。
- 每台服务器给员工的规矩：允许 / 禁止编译、自测，禁止的命令，内存上限（超了提醒，一直超停掉最大的进程），同时最多几个员工（多了排队）；不许 sudo、装系统软件、管系统服务、改系统目录。员工进程降低优先级。
- 开新会话接着做：旧会话归档（员工档案「历史会话」能看），新会话输入框预填交接；会话太长、上下文快满时提示。员工能在 Claude Code 和 Codex 之间换（从记忆仓库接着做），档案里有 work 历史。
- 问题清单：日志值班用 log_scan 巡检、issue_report 记问题（同一个问题合并计数），新的严重问题发卡片：修复 / 已知 / 忽略 7 天；问题清单页能交给员工修。
- 运维工具：log_scan（按时间统计、第一次 / 最近出现、异常汇总、.gz 和 journald）、file_write（先备份）、{{secret:凭证名}} 占位（AI 看不到密码）、工作空间发布目标 + deploy（生产先确认，网页也能点发布）。
- 员工人设（性别、性格）、聊天常用语、用量按项目和按天看。

## server 0.6.0 + web 0.19.0（2026-11-23）
- Agent 指纹：每台 Agent 第一次启动生成自己的 ed25519 密钥（私钥不出那台），每个请求都签名，Opero 按指纹（`SHA256:…`）认机器——换了上报地址也认得，不用重新接入。没带令牌也能接：那台按指纹来连，网页「等你接受」里核对指纹（那台上 `opero fingerprint`）后点接受。
- Opero 指纹：Opero 自己一对密钥，派给 Agent 的活都签名；Agent 第一次连上记住这个指纹，之后只执行它签过名的活（别人冒充地址也指挥不了机器）。迁移：数据目录带过去指纹不变，网页「指纹和迁移 → 换地址」一键让所有 Agent 改连新地址，或在那台上 `sudo opero agent-url <新地址>`；换成另一套 Opero 时带上它的指纹才认。
- 安装命令的令牌可以不带（`--agent <地址>`）。

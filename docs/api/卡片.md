# 卡片

员工发给主人的结构化消息。消息 `kind: 'card'`，卡片在 `message.card`。类型定义见 `code/server/src/types.ts`（`Card`、`CardAction`）。网页的画法在 `code/web/src/components/cards.tsx`，这份文档是各端共同的约定：**加卡片种类、加字段时同步改这里**。

## 结构

```ts
Card {
  id: string            // 卡片自己的 id（按钮接口不用它，用消息 id）
  type: 'issue' | 'confirm' | 'ask' | 'run' | 'generic' | …   // 以后可能加新种类
  v: 1
  state: 'open' | 'done' // open = 还能点；done = 点过 / 失效 / 不用点
  level: 'info' | 'warn' | 'danger'  // 左边色条：蓝 / 橙 / 红
  data: { title: string, … }         // 各种类的字段见下
  actions: CardAction[]
  result?: string | null // done 以后显示的那句（「你同意了」「已交给员工去修」…）
}
CardAction {
  id: string
  label: string
  style?: 'primary' | 'danger' | 'default' | 'ghost'
  panel?: string         // 有它：点了在本地打开一个页面，不调接口（见下）
  args?: Record<string, unknown>
  tool?: string          // 网页内部用，各端可以忽略
}
```

## 通用显示（不认识的种类就这么画）

**每张卡片都有 `data.title`**（后台保证）。下面这些字段有就显示，没有就不显示：

| 字段 | 显示 |
|---|---|
| `data.title` | 标题 |
| `data.tag` | 标题旁边的小标签。带「要你 / 等你 / 待」= 橙色；带「完成 / 已 / 通过 / 正常」= 绿色；其它灰色 |
| `data.rows` | `[string, string][]`，键值行（左边灰字是名字，右边是值） |
| `data.url` | `http(s)://` 开头时给一个「打开 ↗」链接（系统浏览器打开） |
| `actions` | `state === 'open'` 时一排按钮；`done` 时不显示按钮，显示 `result` |

后台加新种类时也会带上这些字段，所以按通用样子画就能看懂、能点，不用每加一种卡片就发 App。

## 点按钮

1. `action.panel` 有值：**不调接口**，在本地打开对应页面（原生页或嵌网页）：
   - `credentialEdit`：加凭证页，`args` 里有 `group`、`kind`（嵌网页的 route：`credentialEdit;group=…;kind=…`）。
   - `diff`、`query`：网页内部用的（看改动、看查询结果），原生可以先不支持。
   - 不认识的 `panel`：嵌网页打开同名页面，或者不显示这个按钮。
2. 否则调 `POST /api/messages/<消息 id>/action`，请求体 `{ action: <action.id>, answer?: string }`，返回 `{ ok: true, result: string }`。卡片随后会通过实时推送更新成 `done` + `result`（有的按钮不改状态，比如合并请求的「刷新状态」）。
3. `style === 'danger'` 的按钮要先验证本人（5 分钟内验过；App 用生物识别 + `POST /api/app/verified`），否则接口回 `403 VERIFY`。
4. 出错：`400`，`message` 是给人看的原因（「已经处理过了」「这个请求已经失效…」），直接提示。

`data.pending === true` 的卡片（confirm、ask）是员工在等主人：员工那一轮还在等这张卡片。那一轮结束了或 Opero 重启过，卡片会变成 `done`，`result` 写原因（「员工这一轮已经结束」/「已失效（Opero 重启过），让员工再发一次」）。

## 后台会发的种类

### `issue`：新问题（日志巡检、员工发现的线上问题）

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | string | 问题标题 |
| `tag` | string | 「新问题」或员工写的一句 |
| `issueId` | string | 问题清单里的 id |
| `rows` | `[string, string][]` | 次数、在哪（服务器 · 项目）、可能原因（有才有） |
| `sample` | string | 日志片段（最多 600 字），等宽字体、可折叠 |

按钮：`fix`（修复，primary）→「已交给员工去修」；`known`（已知）→「标成已知」；`ignore`（忽略 7 天，ghost）→「7 天内不再提醒」。`level: 'danger'`。

### `confirm`：要你确认（员工要做有风险的事）

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | string | 要做什么（人话） |
| `tag` | string | 「要你确认」或「危险」 |
| `note` | string | 谁要做（「opero 开发 要跑命令」），可能为空 |
| `why` | string | 为什么要你点（`open` 时显示） |
| `detail` | string | 具体命令 / 内容，默认收起，点「看具体命令 / 内容」展开，等宽字体 |
| `pending` | true | 员工在等 |

按钮：`deny`（不行，ghost）、`allow`（同意 primary；`level: 'danger'` 时是「确认执行」danger，要验证本人）。结果：「你同意了」/「你同意了 · 已验证本人」/「你没同意，员工已经知道了」。

### `ask`：要你选

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | string | 问题 |
| `options` | string[] | 2–6 个选项，单选 |
| `recommend` | number | 推荐的那个的下标，默认选中它 |
| `pending` | true | 员工在等 |

按钮：一个 `ok`（「就这样」，primary）。点的时候带 `answer: <选中的那个选项的文字>`。结果：「你选了：…」。

### `run`：一轮做完的小结

不画成卡片：是员工这一轮最后一句话下面的一行小字（✓ 本次完成 · 已推送 abc1234 · 3 个文件 +12 −4 · 本次 $0.42 · 会话 $3.10（订阅）· 按钮）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` / `stopped` | boolean | 做完了 / 主人按了停止（都不是 = 这一轮没做完） |
| `git` | string | 提交推送的结果（一句话，比如「已提交并推送到远端（abc1234）」） |
| `ws` | string | 项目 id（不是项目员工就是空） |
| `before` / `after` | string | 开工时 / 做完的提交 |
| `files` / `ins` / `del` | number | 改了几个文件、加 / 删几行 |
| `list` | `{ f: string, a: number, d: number }[]` | 文件明细（点「N 个文件」展开） |
| `cost` / `sessionCost` | number | 这一轮 / 这个会话的花费（美元，执行器报的） |
| `tokens` | number | 这一轮用的 token |
| `billing` | `'sub' \| 'api'` | 订阅额度（花费只是估算）/ 按量计费 |
| `title` | string | 这一轮主人说的第一句（截短） |

按钮（有改动且推送了才有）：`revert`（撤销这次改动，ghost）；`release:<发布目标 id>`（「发布这次改动」/「发布到 X」，primary；发到生产要验证本人，接口会回 `403 VERIFY`）。结果：撤销的说明 /「已开始发布到 X，进度在「发布」里看」。

### `generic`：其它（都按通用样子画）

后台现在用它发这些（都有 `title`、`tag`、`rows`）：

| 是什么 | 认法 | 按钮 |
|---|---|---|
| 员工用 `send_card` 发的结构化结果 | 没有下面这些特征 | 最多 3 个（`b0` `b1` `b2`，第一个 primary）；点了 = 员工收到一句「我在卡片「…」上点了「…」」，结果「你点了「…」」 |
| 合并请求 | 有 `data.pr`、`data.url` | `refresh`（刷新状态）：卡片不变 done，返回的 `result` 是新状态（待合并 / 已合并 / 已关闭 / 有冲突） |
| 要一个凭证 | 有 `data.credReq`（`{ emp, group, kind }`） | `add`（去添加，`panel: 'credentialEdit'`）：本地打开加凭证页，存好后员工自动收到 |
| 发布进度 | `id` 是 `c-<发布 id>` | 没有按钮；`state: 'open'` 表示还在发，`rows` 是每一步（编译 ✓ / 发到服务器 进行中 …），`url` 是编译日志；发完 `done` + `result` |

## 只在试用版（/demo）里出现的

`change`、`release`（带步骤条）、`query`，以及带 `data.ch`（消息渠道）/ `rows` 全是「N 条」（汇总）的 `generic`：是网页假数据里的样子，后台不发。原生端不用专门做，遇到了按通用样子画。

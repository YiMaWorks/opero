# 多端架构

Opero 的界面按平台分开做，各端用自己平台的原生语言；后台只提供接口，各端都通过同一套接口工作。

## 目录

```
code/
  server/          后台：接口（/api/*）+ 实时推送；可以顺带托管网页，也可以只提供接口（OPERO_WEB=none）
  web/             网页：浏览器里用的 Opero、官网、/demo（React + Vite + TypeScript）
  android/         安卓 App（Kotlin；新页面用 Jetpack Compose，逐步替换现在的 WebView 外壳）
  apple/           苹果 App：iPhone、iPad、Mac 一套代码（Swift + SwiftUI）
  windows/         Windows App（C# + WinUI 3）
  desktop/         过渡用：Electron 桌面端（WebView），apple/ 的 Mac 版和 windows/ 能用以后删掉
  design-mockups/  生成设计图、Logo、README 配图的脚本
docs/
  多端架构.md       本文
  api/             接口文档：README.md（约定、登录、实时推送、核心流程）+ 接口清单.md（自动生成）
  规范/             界面、数据、表单与卡片等规范，各端共用
  设计.md           后台和网页的设计
```

| 端 | 目录 | 语言 / 框架 | 编译在哪 | 版本号在哪 |
|---|---|---|---|---|
| 后台 | `code/server` | Node 22 + TypeScript（直接跑，不编译）+ SQLite | 不用编 | `code/server/package.json` |
| 网页 | `code/web` | React 19 + Vite + TypeScript | Linux 上 `npm run build` | `code/web/package.json` |
| 安卓 | `code/android` | Kotlin + Jetpack Compose | Linux（Gradle） | `code/android/app/build.gradle.kts` 的 `versionName` / `versionCode` |
| 苹果 | `code/apple` | Swift + SwiftUI（iOS 17+ / macOS 14+） | 在 Mac 电脑上本地打包（Xcode） | Xcode 工程的 Marketing Version / Build |
| Windows | `code/windows` | C# + WinUI 3（Windows App SDK，.NET 8） | 在 Windows 电脑上本地打包（Visual Studio / `dotnet`） | `Package.appxmanifest` / 项目文件里的版本 |

## 各端和后台怎么连

- **接口是唯一的约定**：各端只认 `docs/api/`。后台加、改接口时同步改文档（`接口清单.md` 用脚本生成），各端照着写；不要在客户端里猜接口。
- **登录**：
  - 网页：账号密码 / 通行密钥登录，会话令牌放 HttpOnly cookie。
  - 原生 App / 桌面端：**每个端自己登录**，不依赖别的端。登录页填 Opero 地址 + 账号密码（`POST /api/app/login`，开了两步验证再 `POST /api/app/login/mfa`）→ 拿到**设备令牌**（存进系统钥匙串 / 密钥库）和**会话令牌**；之后调接口带 `Authorization: Bearer <会话令牌>`。会话过期（401 `AUTH`）用设备令牌 `POST /api/app/session` 再换；设备被断开或改了密码（401 `DEVICE`）回到登录页。网页已经登着时也可以用 6 位配对码登录（可选）。
  - 几个端、几台设备可以同时登着，互不影响。
  - 详见 `docs/api/README.md`「登录」。
- **实时**：`GET /api/events`（Server-Sent Events）推所有变化（新消息、员工在干活、卡片、列表增删改）；断线重连后重新拉一次 `GET /api/bootstrap`。
- **推送**（App 在后台 / 被杀时）：长轮询 `GET /api/app/push`（设备令牌）。安卓、Windows 用常驻连接；苹果在后台不能常驻，以后要做 APNs 中转（见下面「还没定的」）。
- **危险操作验证本人**：App 用系统生物识别（指纹 / Face ID / Windows Hello）验过后调 `POST /api/app/verified`，这台设备 5 分钟内的操作算验过（App 自己的解锁可以更长，那是 App 内部的事）。

## 各端共用的东西

- **界面规范**：`docs/规范/界面.md`、`表单与卡片.md`、`底部菜单.md` 等，各端照着做，长相和交互保持一致（原生控件风格可以随平台）。
- **文案和翻译**：源文是简体中文，网页的字典在 `code/web/src/i18n/`（`source.json` 是全部原文，`locales/<语言>.json` 是译文，七种语言）。原生端用到同一句话时用同样的译文；可以写脚本从这里导出成各平台的资源格式（Android `strings.xml`、Apple `Localizable.xcstrings`、Windows `.resw`），别各自另翻一套。
- **品牌**：Logo、图标、颜色在 `docs/品牌/`、`docs/images/`。
- **数据类型**：后台的类型定义在 `code/server/src/types.ts`（会话、消息、卡片、员工……），接口返回的就是这些结构。

## 怎么推进（原生端）

1. **先做核心**：会话列表、聊天（消息、卡片、插话 / 排队、停止、发图片和文件）、推送、配对和登录、验证本人。这些做成原生的。
2. **其它页面先嵌网页**：员工、项目、服务器、发布、设置这些页面，先在 App 里用 WebView 打开网页对应的页面（用会话令牌免登录进网页），再一页页换成原生。
3. **一个端一个负责人**（各自一个 AI 员工）：只改自己的目录和自己的 README；要后台加 / 改接口，写清楚需要什么，交给后台负责人，别自己改 `code/server`。
4. **各端版本号独立**：动了哪个端就加哪个端的版本号，`docs/变更记录.md` 写「端 + 版本 + 改了什么」。

## 编译和发布

**用 Opero 自己编、自己发**：这个仓库在 Opero 里是一个项目，**每个端是项目里的一个编译组件**（Opero 一个项目可以有多个编译组件，见 `docs/设计.md`「编译组件」），各自的模板、打包工具、流水线、试编译互不影响；每个发布目标选发哪个组件。各端负责人用员工工具自己配，不用别人帮忙：

1. `setup_info` 看现场（仓库平台、能用的凭证、已有流水线、已有编译组件和发布目标）；`build_info` 看已有组件。
2. `build_set component=<组件名> kind=<模板> provider=<打包工具> …` 建自己的组件（名字给一个新的就是新加；已有的就是改）。
3. `build_generate component=<组件名>` 建 / 更新流水线 → `build_try component=<组件名>` 试编 → `build_status component=<组件名>` 看日志，改到编通。
4. 要发布时 `release_target_set name=<目标> build=<组件名> servers=… dir=…` 建发布目标；发生产会先问主人。

各端的组件：

| 端 | 组件名 | 模板 | 在哪编 | 产物 |
|---|---|---|---|---|
| 网页 | 网页 | custom（编译命令把 `code/web` 编好、打成带 `deploy.sh` 的 tgz 放进 `out/`） | 流水线 | `*.tgz` |
| 安卓 | 安卓 | android（`subdir=code/android`，`versionFile=code/android/app/build.gradle.kts`——版本号文件按仓库根目录算） | 总是流水线（`where=pipeline`；开发机上不编 Android） | `*-unsigned.apk`，发布目标配签名证书时部署前签名 |

网页、安卓在 Opero 里编（上面的流程）。**苹果、Windows 在电脑上本地打包**（不走云端 CI、不在 Opero 的流水线里）：

| 端 | 在哪打包 | 怎么打 | 签名 | 产物 / 分发 |
|---|---|---|---|---|
| 苹果 | 一台 Mac（Xcode 15+） | 见 `code/apple/README.md`「打包」 | 我们的 Apple Developer 账号（已付费）：在那台 Mac 的 Xcode 里登录团队、自动签名；App Store Connect API 密钥、公证用的钥匙串配置只放在那台 Mac 的钥匙串里 | iOS / iPadOS：上传 App Store Connect → TestFlight → App Store；Mac：Developer ID 签名 + 公证 + 钉票的 `.dmg` |
| Windows | 一台 Windows 电脑（Visual Studio 2022 / .NET 8 SDK + Windows App SDK） | 见 `code/windows/README.md`「打包」 | 代码签名证书（`.pfx`）只放在那台电脑上；没有证书也能装，会提示「未知发布者」 | `.msix`（或安装器） |

- 证书、密码、密钥、团队编号都不进仓库：苹果的团队编号放在不提交的本地配置里（`code/apple/Config/Signing.local.xcconfig`，仓库里只放 `Signing.example.xcconfig`），拿到开源代码的人用自己的账号就能打。
- 打包前改版本号（苹果：Marketing Version + Build；Windows：`Package.appxmanifest`），`docs/变更记录.md` 记「apple x.y.z」/「windows x.y.z」。
- **打好的包放进项目的「安装包」**（server 0.26.0）：每个端 × 渠道（测试 / 正式）一格、只留最新。安卓：发布目标用 `release_target_set name=安卓测试 build=安卓 package=android:test`（再配签名证书），编完签好自动放进去；苹果、Windows 在电脑上打完，拖进网页项目页「安装包」，或者 `POST /api/workspaces/:id/packages`（见 `docs/api/README.md`「安装包」）。给测试同事用分享链接（带二维码）。
- 签名证书四种都能存进 Opero 的保险箱（「权限和凭证 → 签名证书」）：安卓签名、苹果证书（.p12 + 描述文件）、App Store Connect API Key（.p8）、Windows 代码签名（.pfx）；后三种现在只是存着，等 Agent 能跑在 Mac / Windows 上再由 Opero 自动用。
- 安卓用自己的 keystore，放在 Opero 的签名证书凭证里，发布时签名，不进仓库。

## 还没定的

- **让 Opero 驱动 Mac / Windows 上的本地打包**：Opero 的 Agent 现在只支持 Linux（systemd、`/etc/machine-id`、sudo + bash）。Agent 支持 macOS / Windows 以后，那台 Mac / Windows 电脑可以接进 Opero，编译组件选「本地编在这台」，苹果、Windows 也能和网页、安卓一样在 Opero 里试编、发布。在那之前由各端负责人在电脑上手动打包（上面的表）。

- 苹果的推送：iOS App 在后台拿不到长轮询，要发 APNs。自部署的 Opero 没有我们的推送证书，可能要一个可选的推送中转服务，或者让用户用自己的 Apple 开发者账号。
- 原生端和网页的页面对照表（哪些页面先原生、哪些先嵌网页）在各端 README 里维护。

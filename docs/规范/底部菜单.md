# 员工底部菜单（二开说明，v0.1，2026-11-22）

> 已定的：每个员工底部那排菜单要有，但**内置的只放少量常用项**，要什么菜单让使用者自己二开。这份文档就是二开说明。

## 是什么

- 聊天输入框上面那一排按钮（像服务号的底部菜单）。**点了直接打开一个页面 / 面板，不经过 AI**，秒开、不花钱。
- 看列表、看记录、看状态这类「固定操作」走菜单；要理解、判断、多步骤的才找 AI。
- 手机上最多显示 3 个，多了自动收成「更多」。

## 现在内置的（`code/web/src/menus.ts` 的 `MENU_REGISTRY`）

| 菜单名 | 打开 | 来自 |
|---|---|---|
| 问题清单 | 这个员工负责项目的问题 | 内核 |
| 查生产库 | 查询台（只读账号） | 数据插件 |
| 发布记录 / 应用 | 发布记录 / 应用和环境 | 发布插件 |
| 改动记录 / 预览 | 员工工作空间的详情（提交、分支、预览） | 内核 |
| 服务器 | 服务器列表 | 服务器插件 |
| 员工 / 用户 / 设置 / 插件 | 对应管理页 | 内核 |
| 日志扫描 | 触发器 | 服务器插件 |

没登记的菜单名会打开一个占位页，提示「去二开」。

## 怎么给员工配菜单

- **不写代码**：员工档案 →「编辑」→「底部菜单」填菜单名，逗号隔开（只能用已登记的名字）。
- 或者跟「系统管家」说：「给 shop 日志值班加一个『发布记录』菜单」。

## 怎么加一个新菜单（二开）

### 现在（网页原型）

在 `code/web/src/menus.ts` 的 `MENU_REGISTRY` 里加一项：

```ts
订单导出: {
  plugin: 'order-export',          // 来自哪个插件
  desc: '按日期导出订单',            // 编辑员工时给人看
  route: () => ({ page: 'placeholder', params: { title: '订单导出' } }),  // 打开哪一页
},
```

- `route` 能拿到 `{ employeeId, workspace }`，可以按员工打开不同内容（例如改动记录打开它自己的工作空间）。
- 页面可以是内核已有的页面（`src/pages/index.tsx` 里的页面名），也可以是新写的页面（加到 `src/pages/` 再在路由表登记）。

### 正式版（插件）

插件在清单里声明，加载时自动登记到同一个注册表，不用改内核：

```yaml
# plugins/order-export/plugin.yaml
menus:
  - name: 订单导出
    desc: 按日期导出订单
    ui: ui://order-export/export     # 插件自己的界面（MCP Apps，沙箱里跑）
    # 或者：page: query               # 打开内核页面
    defaultFor: [shop-log]            # 可选：装上后默认加到哪些员工
```

- 界面按 `docs/规范/表单与卡片.md` 第 4 节写（MCP Apps）；界面里要做事一律调工具，照样过判定、记审计。
- 菜单本身不需要权限；打开的页面 / 工具按用户和员工的权限显示和执行。

## 约定

1. 菜单名短（2～4 个字），一个员工默认不超过 3 个。
2. 菜单只做「看」和「固定操作」；需要 AI 思考的不要做成菜单。
3. 插件停用后，它登记的菜单自动消失，员工配置里的名字保留（再启用就回来）。

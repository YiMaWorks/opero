# 界面规范

所有页面照这一份做：长得一样、用起来一样。改组件、加页面前先看这里；样式在 `code/web/src/styles.css`，组件在 `code/web/src/components/ui.tsx`。

## 1. 原则（先看这个）

1. **能点不填，能自动不问**。默认值替用户想好（端口、名字、分支、服务器、环境标签），用户只在想改的时候才动。必须手填的只剩密码、令牌、Key 这类只有用户知道的东西。
2. **一屏一件事**。主操作只有一个（`btn primary`），其它是 `default` / `ghost`。一般不用动的设置收进「高级设置（一般不用动）」。
3. **不要「给自己看的备注」输入框**。名字不填自动起，说明文字由系统生成。
4. **每个要去别处拿东西的地方都要有指引**：直达链接按钮 + 一步步的步骤 + 要给的权限 + 能复制的命令（见 `credmeta.ts`）。
5. **确认只留给危险操作**：删除用确认框（`confirm`）；发布生产、在生产服务器 / 生产库上改东西、看密码明文、账号安全设置才「验证本人」。其它直接做，记进操作记录。
6. **常用操作放外面**：置顶、发消息、切分支这类每天都用的，放在列表行上 / 页面顶部，不藏进菜单。

## 2. 布局

- 电脑：左边窄栏（页签）· 目录（340）· 内容。内容区最宽 880，居中。手机：一页一页进，底部页签。
- 页面头（`PageHeader`）：标题 + 一行说明 + 右边最多两个按钮。
- 内容由一组组 `Section` 组成：标题在卡片外（左边粗体，右边放这一组的操作，如「+ 加一个员工」「授权凭证」），内容在卡片里。

## 3. 组件怎么选

| 要做的 | 用 |
|---|---|
| 一行信息 / 进下一页 | `Row`（标题、灰字说明、右边值或按钮、可点就带箭头） |
| 2～5 个互斥选项 | `Segmented` |
| 6～15 个选项、多选、标签 | `chips`（`chip`，选中 `on`）；末尾可接一个 `chip-input`「别的」 |
| 选项很多（凭证、仓库、文件） | 右边侧滑 `Drawer`（带搜索、分类筛选、勾选、底部「确定」）；仓库 / 文件用列表 + 搜索 |
| 小表单 | `Sheet`（电脑居中，手机底部） |
| 服务器上的路径 | `PathInput`（输入框 + 「选…」浏览） |
| 服务器上的服务 | `ServicePick` |
| 开关 | `lrow` + `Toggle`，右边说明一句后果 |
| 提示 | `banner b-info / b-ok / b-warn`；字段下面一句 `field-hint`；页面底部 `hint` |
| 空状态 | `Empty`：说清楚下一步点哪里 |
| 状态 | `Tag`：ok 绿 / warn 黄 / danger 红 / mute 灰；环境标签用 `envTone` |
| 获取步骤 | `cred-guide`：标题「怎么拿」+ 直达按钮 + 有序步骤 + 权限 + 可复制代码块 |

## 4. 颜色、字号、间距

- 颜色全用变量（`--primary` `--text` `--sub` `--faint` `--line` `--panel` `--ok` `--warn` `--danger`），深色 / 浅色主题自动换；不写死颜色（分类图标的点缀色除外）。
- 字号：页标题 17，正文 14，说明 12～12.5，标签 12。
- 圆角：按钮 8，输入框 10（`--radius`），卡片 12～14，标签全圆。
- 间距：组和组之间 24，卡片内边距 14～16，标签之间 8。

## 5. 文字

- 口语、短句、先说结论；按钮用动词（「接入」「授权凭证」「切换分支」），不用「确定」「提交」这类空词（对话框底部除外）。
- 说明最多两行；更长的放「怎么拿」步骤里。
- 不写内部实现词（API、字段名），除非用户真的要填它（比如 `{{secret:名字}}`）。
- 所有界面文字是简体中文源文，改了以后跑 `node scripts/i18n-extract.mjs` 补 6 种语言（见 `code/web/src/i18n/GLOSSARY.md`）。

## 6. 新页面自查

- [ ] 有没有能自动补 / 能点选却让人填的字段？
- [ ] 主操作是不是只有一个？一般不用动的收进高级了吗？
- [ ] 要去别的平台拿东西的地方有没有直达链接和步骤？
- [ ] 列表多了（> 15 项）会不会挤？要不要改成侧滑 + 搜索？
- [ ] 确认 / 验证本人是不是只在危险操作上？
- [ ] 手机上能不能用（宽度 360 看一眼）？

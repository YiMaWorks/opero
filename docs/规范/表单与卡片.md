# 表单与卡片规范（草案 v0.1，2026-11-21）

> 解决 KidLock 痛点 #2：每种卡片网页和 App 各写一遍、App 要发版、样式不统一。
> 配图：`界面设计/opero-v1-卡片.png`（每种卡片长什么样）、`opero-v1-网页.png`、`opero-v1-手机.png`。
> 原则：**卡片只有一份描述（JSON）、一套渲染（网页组件）**；网页、桌面、App 都用这一套。

## 1. 会话里的每一条 = 一条消息

```json
{
  "id": "m_9f2",
  "session": "s_12",
  "from": { "type": "employee", "id": "mov-log" },   // employee / user / system
  "kind": "card",                                     // text / status / file / system / card / app
  "card": { … },                                      // kind=card 时，见第 2 节
  "created_at": "…", "updated_at": "…"
}
```

| kind | 是什么 | 谁产生 |
|---|---|---|
| `text` | 员工 / 人说的话（Markdown） | 执行器输出、人输入 |
| `status` | 「在做什么」一行小字，会被下一条覆盖，不进历史 | Agent 读执行器事件自动产生 |
| `file` | 文件、图片、日志片段 | `session.send_file`、人上传 |
| `system` | 系统提示：触发（扫描发现）、转来（别的员工交回） | 后台 |
| `card` | 内核固定卡片（第 2 节） | **工具的副作用**（第 3 节） |
| `app` | 插件自定义界面（MCP Apps） | 带 `ui` 的工具 |

## 2. 卡片描述

```json
{
  "type": "change",              // 卡片类型，见下表
  "v": 1,
  "state": "open",               // open 可操作 / done 已处理（变只读摘要）；不过期
  "level": "info",               // info / warn / danger —— 决定推不推送（第 5 节）
  "data": { … },                 // 按类型的字段
  "actions": [
    { "id": "revert", "label": "撤销合并", "style": "ghost",
      "tool": "workspace.revert_merge", "args": { "merge": "mg_31" } },
    { "id": "view", "label": "看改动", "panel": "diff", "args": { "merge": "mg_31" } }
  ],
  "result": null                 // done 后：谁点的、点了什么、结果一句话
}
```

- **按钮 = 工具调用**（`tool` + `args`），点了走网关（channel = card，身份是点的人）：判定、审计照常；危险的按钮自动要求验证本人。**卡片自己不执行任何东西。**
- 按钮也可以只是打开面板（`panel`），不经过网关写操作。
- 点完：卡片 `state` 变 `done`，显示 `result`；结果作为一条消息交回员工（在跑就插话，没跑就开一轮）——照 KidLock 的 `continueSession`。
- 卡片能**原地更新**（发布进度、检查进度）：后台按 `id` 推更新，界面替换。

### 内核卡片类型（第一版）

| type | 用途 | 主要字段 | 典型按钮 |
|---|---|---|---|
| `issue` | 问题 | 编号、标题、严重程度、影响、原因、建议、证据（日志 / 查询的引用） | 修复 · 先盯着 · 忽略 |
| `change` | 改动 | 项目、分支、文件列表（+/−）、检查结果、合并状态 | 看改动 · 撤销合并 |
| `release` | 发布 | 应用、环境、版本、步骤进度、发布后观察 | 回滚 |
| `query` | 查询结果 | 数据源、SQL、列、前 N 行、总数、耗时 | 展开 · 导出 · 存成菜单 |
| `confirm` | 要你确认（只有危险操作 / 发起人没权限） | 一句人话（工具的 `confirm_text`）、具体内容、撤销方式 | 确认（指纹）· 不做 |
| `ask` | 员工提问（`core.ask_user`） | 问题、字段（单选 / 多选 / 文字 / 数字 / 是否），AI 推荐值 | 提交 |
| `generic` | 通用：标题 + 标签 + 键值行 + 小标签 + 按钮 | 插件不用写界面就能出简单卡片 | 自定义 |

插件要比 `generic` 复杂的界面 → 用 MCP Apps（第 4 节），不新增内核卡片类型。新增内核类型 = 改内核，要走内核变更。

## 3. 卡片从哪来：工具的副作用，不是 AI 自己拼

- AI 只做两件事：**说话（text）、调工具**。卡片由工具 / 系统产生，所以格式永远一致，AI 不会拼错。
  - `issue.report` → `issue` 卡；工作空间每轮改完 + CI 检查 → `change` 卡；发布插件 → `release` 卡；`db.query` → `query` 卡；网关判定「要确认」→ `confirm` 卡；`core.ask_user` → `ask` 卡。
  - 插件的工具想出卡片：在结果里带 `card`（`generic` 或自己的 MCP Apps）。
- 通用的 `session.post_card` 只允许 `generic`。

## 4. MCP Apps（插件自定义界面）

按 `MCP设计.md` 第 7.1 节：`ui://插件/名字`，mimeType `text/html;profile=mcp-app`，工具 `_meta.ui.resourceUri`，宿主用官方 `app-bridge`，沙箱 iframe（另一个域名）。宿主传：主题（浅 / 深 + 设计系统颜色变量）、语言、当前用户标签。Opero 提供表单组件库（`@opero/ui`：输入、下拉、选服务器 / 应用 / 凭证 / 员工、表格、确认区），插件用它写出来的表单和内核卡片长得一样。

## 5. 推送和会话列表（2026-11-22 改：像微信，不单列「等我处理」）

- **会话列表就是一列聊天**：用户置顶的员工在最上面（长按 / 右键 → 置顶，多了可折叠成「N 个置顶聊天」），其余按最近一条消息时间排。**不在顶部单列「等我处理」**。
- 要你处理的（`confirm` / `ask` 没处理）：那个会话的预览前面加红字 `[要你确认]` / `[等你回答]`（像微信的「[有人@我]」）+ 未读数，并推送。
- 免打扰的会话：不推送，未读只显示红点，预览右边一个静音图标。
- 桌面客户端托盘里的「等我处理」列表保留（那是系统托盘，不是会话页）。

| 卡片 | 预览前缀 | 推送 |
|---|---|---|
| `confirm`、`ask`（没处理） | 红字 `[要你确认]` / `[等你回答]` | 是（常驻连接推；一人一套没有厂商推送，App 被杀后靠 Telegram / Slack / 邮件兜底，见 `规范/App外壳.md`） |
| `issue` 严重 | — | 是 |
| `issue` 一般、`change`、`release` 成功 | — | 否（会话里看） |
| `release` 失败 / 自动回滚 | — | 是 |

免打扰的会话不推；严重的「追着响」照 KidLock（没送达改短信 / 邮件）。

## 6. 三端怎么渲染

- **一套网页组件**（React）：消息列表、所有卡片、面板（看改动、看日志、查询结果、库表结构）、MCP Apps 宿主。网页、桌面壳直接用。
- **App = 原生外壳 + WebView**（2026-11-22 改：会话列表也放 WebView，整个界面一套网页；外壳照 KidLock 安卓做，见 `规范/App外壳.md`）：
  - 原生只做：连接你的 Opero、常驻推送、指纹（JS 桥）、点通知直达、选文件 / 拍照、麦克风、返回键、状态栏颜色、App 内更新。
  - 页面、聊天、卡片、面板全在 WebView 里，和网页同一套代码。**加卡片、改样式都不用发 App**。
- 卡片宽度自适应：网页 ≤ 520，手机占满（减去头像），字段多的自动折叠成「展开」。

## 7. 设计系统

### 7.0 风格（主题）：精选 14 套 + 自己配色（0.9.1，`code/web/src/themes.ts`，预览 `界面设计/opero-风格.png`）

已定（0.9.1）：不硬凑数量、不固定三个颜色，要好看、参考业界，每套有名字。
- **每套都有名字和出处**，基础是「底色 / 字色 / 跳色」，需要讲究的单独写：左栏颜色、面板、分割线、气泡渐变另一端、毛玻璃整页背景。
- 浅色 7 套：紫晶（Opero 默认，深紫左栏）、冰川（KidLock，深海军蓝左栏）、微绿（照微信电脑版）、纸本（KidLock，方角）、奶油（硅谷创业官网：奶油 + 墨黑 + 焦橙）、墨白（Vercel 黑白）、晨雾（KidLock，淡紫淡蓝毛玻璃）。
- 深色 7 套：石板（Opero 默认深色，Linear 那种）、夜航（KidLock，荧光绿）、炭灰（炭灰 + 沙色 + 电光蓝）、海军（海军蓝 + 亮粉）、暮光（KidLock，暖黑琥珀）、琉璃（KidLock，深蓝毛玻璃）、高对比。
- 选择时每套是一个缩小的界面（左栏 · 两行字 · 一张卡片带跳色），照 KidLock 的风格选择。
- 入口：手机会话页顶栏左边、电脑左边一栏「风格」按钮（快捷切换）；完整的在设置 → 外观 → 风格（跟随系统：浅色 / 深色各选一套；固定一套；自己配色：浅底 / 深底 + 三个取色器）。
- 状态色不跟风格变（只分浅色一套、深色一套）：要你处理永远是橙、出错永远是红。
- App 外壳：网页把底色和面板色交给外壳（`OperoNative.setBars`）。

（2026-11-22 照 KidLock 聊天样式改，代码 `code/web/src/styles.css`）

- **布局（电脑）**：所有页签统一三栏（照微信电脑版）：左栏 76（≤1100 时 60）· 目录 340（会话页是会话列表，其它页签是 `SideNav` 目录：搜索 + 主操作 + 条目，选中整行跳色填满）· 内容；聊天右侧面板 480。手机 ≤ 860。
- **会话一行**：44 圆角方头像（淡底彩字）、名字 14/600、预览 12.5；在干活 = 头像右下蓝色跳动点 + 预览变蓝带跳动点；等你 = 预览前橙字「[要你看]」+ 红色未读数；置顶底色深一点。
- **聊天像 IM**（0.11.0）：每条消息带头像（员工左、你右）、气泡带尖角、时间不同插时间分隔、长按 / 右键菜单（复制 / 引用 / 转给别的员工 / 删除）、往上翻时新消息提示「↓ N 条新消息」；顶栏标签后面显示 work 所在服务器的 CPU / 内存（≥80% 橙、≥90% 红）。
- **聊天（0.7 的样子，头像部分已被上一条替换）**：顶栏 68 高（44 头像、名字 17/700、「在干活」胶囊、职务 / 执行器 / 服务器 / 分支小标签）；消息区不放头像；AI 气泡 `4 14 14 14` 圆角、淡线框，按 Markdown 显示（代码块带「复制」）；我的气泡 `14 14 4 14`；离底部 120px 以内才自动滚到最新。
- **输入区（电脑）**：底部白条：第一行 模型 / 思考 / 审核方式 / 上下文 + 底部菜单；第二行 ＋ · 输入框（2～6 行）· 发送；最下一行快捷键提示。**手机**：44 高圆角输入条 + 44 圆形按钮（发送主色、在干活时是红色停止）。
- **卡片**：细边框 + 左边一条圆头 3px 色条（要你确认 / 要你看 = 橙、问题 = 红、改动 / 提问 = 主色、发布 = 蓝；处理完去掉色条、稍淡），圆角 12，最宽 640。标签：要你做的橙、做完的绿、其它灰。
- **卡片主次**（0.7.2）：头部第一行小字（类型 · 标签 · 时间），第二行标题 15.5/600；正文里最重要的一块（消息原文、问题现象）用引用块突出，解释性的话淡色小字；按钮只有一个实心主按钮放最前，ghost 按钮是靠右的文字链接。
- 字体：Geist Sans / 苹方 / 微软雅黑 / 思源黑体；代码 Geist Mono。正文 14，聊天 13.5（手机 15）。
- 页面出错兜底：显示「这个页面出错了」+ 错误 + 再试 / 刷新，不白屏；发版后加载不到旧文件自动刷新一次。

# 主线场景：在手机上查 bug → 改代码 → 发布（2026-11-21）

> 已定的目标：「解决开发问题，查 bug，在线改代码，发布，通过 App 全部搞定。」
> **更正（同日）**：这条线**在 KidLock（旧后台）里已经全部走通**。所以 Opero 不是去发明它，而是把走通的东西**规范化（定规范）、做漂亮（漂亮界面）、做成可二开（支持二开）**。下面第二节「要补的」原稿是按「没做过」写的，要改成「KidLock 怎么做的 → Opero 怎么做得更好」，**等能读 KidLock 代码后逐项对照**。
>
> 这是 Opero 第一版的**北极星**：规范、界面、功能都拿这条线来检验——**走不通这条线的不做，不服务这条线的往后放**。

## 一、一次完整的走法（以 mov-market 支付失败为例）

| # | 发生什么 | 人在手机上看到 / 做什么 | 背后要有什么 |
|---|---|---|---|
| 1 | 线上报错变多 | 推送：「mov 日志值班：支付失败 37 次，已开始查」 | 触发器（日志 / 监控 → 员工）；**手机推送** |
| 2 | 员工查日志、查库、读代码 | 会话里一行小字「在查日志… 在查库…」，不用管 | 日志工具、查库（`规范/数据.md`）、读工作空间代码 |
| 3 | 员工给结论 | 问题卡片：原因、影响、证据（日志片段、查询卡片可点开）、建议「改 X」 | 卡片规范；日志 / 查询结果在手机上能看 |
| 4 | 人说「修」（按住说话也行） | 一句话 | 语音输入 |
| 5 | 员工在分支上改代码 | 「在改 PayService.java…」 | 执行器在工作空间里改；自动建分支 |
| 6 | 员工给改动 | **改动卡片**：改了哪几个文件、手机上能看的 diff（单栏、可折叠、语法高亮）、它自己的说明 | diff 组件（手机优先） |
| 7 | 自动起预览、跑检查 | 「预览已起：链接」+ 检查结果（编译 / 测试通过与否） | **任意项目的预览环境**；按服务器策略放开编译 / 测试 |
| 8 | 人点预览看一眼，点「合并并发布」 | 发布卡片 → 指纹 | 合并 + 发布（发布插件）；生产 = 发版，有权限直接做，指纹验本人 |
| 9 | 发布后盯一会儿 | 「已发布 v1.4.2，10 分钟内没有新报错」；有问题一键「回滚」 | 发布后自动观察（触发器）；回滚 = 撤销 |
| 10 | 记下来 | 问题自动关掉，交接 / 变更记录员工自己写 | 问题清单；项目文档规范 |

全程人只做了三件事：**看结论、说「修」、按指纹发布**。

> 对照结果见 `KidLock对照.md`：推送、diff、问题清单、发布失败自动修 KidLock 已有（照搬改进）；**真正新做**的是分支 + 隔离检查 + 自动合并、统一发布后观察回滚、一个员工改多个仓库。

## 二、这条线涉及的能力（原稿按「没做过」写，待和 KidLock 实现逐项对照）

| 要补 | 说明 | 落在哪 |
|---|---|---|
| **手机推送** | App 是主入口，「等我处理」必须推得到。安卓国内没有 Google 推送，要用厂商推送 / 第三方推送 / App 自己保持长连接 | 原来标「插件」→ 改为**内核**；技术方案待调研 |
| **改动卡片 + 手机 diff** | 手机上看得懂代码改动：单栏、按文件折叠、只看改的地方、长行自动换行 | 表单与卡片规范；设计系统重点组件 |
| **任意项目的预览环境** | 原来只给 Opero 自己（后台开发员工）设计了预览；现在所有项目改完都要能预览 | 新增「预览」能力：分支 → 预览实例（端口 / 子域名）→ 链接；用完自动回收 |
| **分支 → 合并** | 员工改代码默认在分支上，人点「合并」才进主分支；支持 Codeup / GitHub / Gitea | 工作空间规范（新增） |
| **问题清单** | bug 从发现到关闭串起来：问题 → 会话 → 分支 → 预览 → 发布 → 关闭 | 原是私有插件 → 改为**内核**（轻量版），这就是「需求 / 任务跟踪」 |
| **发布后观察 + 回滚** | 发完自动盯报错，坏了一键回滚 | 发布插件 + 触发器 + 撤销 |
| **手机上看日志 / 查询结果** | 日志片段高亮、可搜索；查询卡片横向滚动 | 设计系统组件 |
| 在线改代码（人自己改） | 偶尔人想自己改一行：手机上能打开文件、改、提交 | 第一版：只做「对着 diff 说哪里要改」；手机上直接编辑代码往后放【待定】 |

## 三、对之前问题的回答

上一轮问的「开发管理可能还缺的四项」，按这条主线：
- 需求 / 任务跟踪 → **问题清单进内核**（轻量）。
- 代码审查和合并 → **进**（改动卡片 + 合并按钮）。
- 任意项目预览环境 → **进**。
- 项目文档规范 → **进**（员工自己写交接 / 变更记录，像本仓库这样）。

# opero 设计

> 还没开发。需求原文在 `需求.md`（以它为准），下面是从需求里摘出的设计骨架，开发时再细化；标「待确认」的要确认。

## 一句话
以聊天为入口、由 AI 员工驱动的开源后台：「员工 → 聊天 → 员工去做」，不是「菜单 → 页面 → 按钮」。**重新设计**，不沿用传统后台的表。

## 核心概念
员工 · 项目 · 会话 · 授权 · 资源 · 凭证。员工、资源、凭证互相独立，只靠授权（`grant`）连起来。（详见 `需求.md` 第 1 节）

## 模块（`需求.md` 第 12 节）
- 入口：网页（聊天，三栏）· 桌面壳（同一套网页）· 安卓 App（Compose 外壳 + WebView 表单）· 员工对外接口
- 后台：账号 · 员工 · 资源 · 凭证 · 授权与申请 · **判定** · 会话与卡片 · 派活编排 · 文件 · 通知 · 审计 · 工具注册 · 插件加载
- Agent（Go，必装）：主动连出、执行 / 只读查询、沙箱跑执行器（Claude Code / Codex / Qwen Code / CodeBuddy Code）、资源上限、监控、自动升级
- 存储：MySQL · 文件目录 · 员工的 git 仓库

## 技术栈（需求建议，待确认）
Node + Fastify + React + MySQL + Go Agent；桌面壳 Tauri 或 Electron（未定）；安卓 Compose。

## 代码目录（2026-11-25 定）
`code/server`（后台，只提供接口也行）、`code/web`（网页 + 官网 + /demo）、`code/android`（Kotlin）、`code/apple`（SwiftUI：iPhone / iPad / Mac）、`code/windows`（C# + WinUI 3）、`code/desktop`（Electron 过渡版，原生桌面端能用后删）。各端都走同一套接口；分工、登录、实时、共用资源见 `docs/多端架构.md`，接口见 `docs/api/`。

## 关键设计决定（来自需求）
1. **唯一判定函数**：`判定(谁, 通过哪个员工, 动作, 资源) → 允许 / 要确认 / 要申请 / 拒绝(原因)`；AI 调工具、表单提交、底部菜单、面板按钮显隐全走它；二开在这里挂规则。
2. **工具自声明**：所属员工、动作名、风险级别（读 / 写 / 危险）、资源类型。
3. **权限两标签**：管理员 / 普通用户；员工用资源靠长期授权或单次申请；自动审核开关（危险操作永远不能自动）。
4. **环境只做生产保护**，不参与权限；改生产先出确认卡片 + 验证本人（30 分钟有效）。
5. **AI 永远拿不到凭证明文**，只拿编号；防线写在代码里不靠提示词。
6. **表单 = MCP Apps**（`ui://插件/表单`），沙箱运行，经宿主转工具调用；通用「提问」工具兜底。
7. **插件优先、不改内核**；后台开发员工改自己：先预览再上线、健康检查不过自动回滚、不能改授权 / 审计 / 验证本人代码。
8. 审计一条不落。

## 前端结构（2026-11-22，`code/web` 0.2 定下）
- **数据仓库 `store.ts`**：页面只从这里读（`useStore(选择器)`）、只调这里的动作（发消息、改卡片、置顶、存员工、批申请、存凭证……）。接后台时：初始数据 → 调接口；消息 / 卡片更新 → 服务器推送写进 store；动作 → 调接口。页面不改。
- **页签分工（web 0.41.1）**：会话 · 员工 · 项目 · 应用 · 我（手机也有「应用」页签）。「我」只放个人的（资料、我的习惯、外观和通知、账号安全）；配置都在「应用」：应用磁贴 + 「这套 Opero 的配置」（`LIVE_CONFIG` / `DEMO_CONFIG`：AI 执行器、用量和成本、系统设置 `system`、关于）。原来的「设置」拆成个人的「外观和通知」（`settings`）和「系统设置」（`system`：生产保护、每轮小结、AI 用不了时、提醒发到哪、开机向导）；员工底部菜单「设置」打开系统设置。见 `docs/规范/界面.md`「布局」。
- **页面 = 路由 + 导航**：`pages/index.tsx` 页面名 → 组件；每个页签一摞页面（进下一页 / 返回）；聊天右侧面板也是一摞页面（员工底部菜单打开的就是这些页面）。页面只拿到 `Nav`（push / back / close / openChat），不关心自己在页签里还是面板里。
- **返回**：每打开一层（聊天、页面、面板、弹层、验证本人）记一步浏览器历史；侧滑 / 返回键只关最上面一层。
- **凭证**（`code/web/src/credmeta.ts` 目录 + `code/web/src/pages/creds.tsx` 页面 + `code/server/src/creds.ts` 测试连接）：`Credential { group, kind, meta, user, test, env, aiAllowed }`，值在保险箱。分类：服务器 / 数据库 / 代码仓库 / 云账号 / AI / 签名证书 / 消息渠道 / 其它；类型和步骤、链接只在 credmeta.ts 里。保存时 `testCred` 真连一次（数据库查 SELECT 1、git 平台 /user、云「我是谁」、AI /models、SSH 登录、Redis PING），结果存 `test`。数据库 SQL 类凭证同步成一个 `DataSource`（`credential` 指回它）。
- **验证本人（needVerify）只用在**：账号安全（通行密钥、两步验证、配对码）、看凭证明文、危险卡片、删 DNS 记录、Agent 换地址、受保护（生产）服务器上的非只读命令、受保护库的改数据。其它新增 / 保存 / 授权 / 发布都不验证，只记操作记录。
- **项目员工**：接入仓库时自动建（`projectEmployee`），`workspace` 指向项目；记忆 = 项目 `docs/`（`memory.projectOf`），不建员工记忆仓库；同项目多个员工共用目录，切分支（`branch.ts`）大家一起换。
- **编译看资源**（`policy.ts`）：`Policy.build = auto | on | off`；auto 时编译命令先按 `buildNeed` 估需要，用那台当时的资源（`policy-check.ts` 本机读 / `tools.ts hostRes` 远程读）比，留足余量才放行；拦截小脚本给 Gradle / make / cargo 限并发。
- **编译 / 流水线**（`build.ts`、`pipelines.ts`、`buildjobs.ts`，规范见 `docs/规范/打包工具.md`）：`BuildCfg.where`（auto / local / pipeline）+ `provider`（yunxiao / github / gitlab / jenkins / local）；auto 时 `decideWhere` 按当时资源选；接入项目时 `autoConfig` 认类型建流水线；其它打包工具靠源码 / 产物两个一次性地址打通；员工工具 build_info / build_set / build_generate / build_try / build_status。资源保护 `limits.ts watchResources`：内存、CPU 都是「先提醒、持续超才处理」，CPU 是先暂停再继续。
- **什么时候要主人确认（定死的清单，加新的要先改这里）**：个人助理按约定做事，只有不可撤销或影响生产的才问。
  - 员工自己终端里的命令（照 KidLock）：不弹卡片。灾难性的（删根 / 家目录、格式化 / 分区、写磁盘设备、关机重启、fork 炸弹、chmod -R 777 /、curl | sh）直接拒绝并把原因告诉员工，主人也不在这里批（`ssh.ts CATASTROPHIC`）；别的都直接跑——员工是没 root 的 AI 用户，资源有看守兜底。
  - 员工那边会弹卡片的：① 用 server_exec 在别的服务器上（root）跑危险命令（删根 / 系统目录 / 一两层的大目录、格式化、关机、删库、强推；命令里的简单变量赋值先代进去再判断，`ssh.ts DANGER`）；② 在生产（受保护）的服务器上跑改东西的命令、改文件；③ 在生产服务器上把目录登记成「员工能改」；改生产库的数据，或者危险 SQL（drop / truncate / 不带 where 的 update、delete）；④ 发布目标设成「发前问你」的（新建目标默认：有生产服务器的问，测试 / 开发直接发）；⑤ 删 DNS 记录；⑥ 员工自己用 confirm 问的（规矩里写了只为不可撤销、影响生产的事问）。审核方式不是「自动」的员工（主人自己选的）按它的方式多问。
  - 主人自己「验证本人」的：账号安全（通行密钥、两步验证、配对码）、看凭证明文、危险卡片、删 DNS 记录、所有 Agent 换地址、发生产 / 回滚生产、生产服务器上的非只读命令、生产库改数据。
  - 其它（同步代码、临时文件、测试 / 开发环境的改动、建员工、改设置、授权凭证、试编译、建流水线…）一律直接做，只记操作记录。
- **一轮的小结**（`settings.runSummary`，默认开）：开工记项目提交 `before`，干完提交推送后比 `before → HEAD`，以员工名义发 `type: 'run'` 卡片（data：ok / stopped / git / files / ins / del / list / cost / sessionCost / billing / before / after / ws）。按钮 `revert`（`autogit.revertRun`：一个反向提交 + 推送，不改历史）、`release:<发布环境 id>`（`releases.start`，生产验证本人）。会话累计花费存 `Session.cost`。
- **员工自己接入**（`setup_info` / `pipeline_read` / `release_target_set` / `request_credential`）：平台只管 key 不给 AI 看、危险操作要人点；看现场、配编译和发布目标是员工的活。员工建的发布目标：有生产服务器的一律 ask，不能放松主人设过的权限；部署目录自动登记成「能部署」。`request_credential` 的卡片 `data.credReq = { emp, group, kind }`，新凭证存好时按分类 / 类型匹配，自动授权给那个员工并发消息。
- **配置页 = 看 + 一句话**（`components/AskBar.tsx`）：配置类的事不让人填表，`POST /api/employees/:id/ask` 把一句话（带上在哪个页面说的）交给员工，员工用工具配（schedule_set、server_dir_set、log_register、release_target_set、build_set…）；页面只看、开关、跑一次、删，原表单收进 `Manual` 兜底。新加配置功能时先加员工工具，再在页面放 AskBar。
- **整实例数据库**：`DataSource.db` 为空 = 整个实例，`dbs` 是能看到的库；`db_query` 的 `db` 参数选库。
- **员工授权**：`Employee.creds`（凭证 id）+ `credGroups`（以后新加的这几类自动给）。员工工具用到凭证都过 `credBlock`；`fillSecrets(text, emp)` 只换勾了的；不传 emp 的是主人自己配的（发布的部署命令）。
- **选服务器路径**（`components/PathPicker.tsx`）：`GET /api/servers/:id/ls?path=` 列一层（只读，`find -maxdepth 1 -printf`，目录在前）；`PathInput` 的 `base` 限定在某目录里并返回相对路径。
- **登记的日志** `Server.logSrc`（file / dir / service）：网页「日志」里登记、看；`log_scan` 不给 file / service 时扫全部登记的（dir 展开成 `dir/*.log`）；`GET /api/servers/:id/logs` 支持 `dir=` 和带 * 的 `file=`（看最新的那个文件）。
- **网址**（`router.ts`）：当前页签、开着的会话、页面那一摞、面板写进 `#/` 后面（如 `#/chat/<会话>`、`#/workspace/workspace;id=w1/release;id=r3`、面板接在 `/~/` 后），界面一变就 `replaceState` 改当前这条（不多记历史），刷新 / 自动更新重载 / 复制网址都回到原页；没登录时不改，登录完回到原来那页。只记字符串、数字参数；页面内部的小状态（页里的切换、滚动位置）不记。用 `#` 是为了不需要服务器配合（子路径、/demo、桌面端、App 都一样）。
- **卡片按钮 = 工具调用**：现在在 `App.tsx` 的 `onCardAction` 里按类型模拟；接网关后统一改成「调工具 → 结果写回卡片」。
- **危险操作统一走 `requireVerify`**（验证本人弹层），审计统一走 `audit()`。
- **主题**：`styles.css` 颜色全是变量，`:root[data-theme=dark]` 换一套；跟随系统 / 浅 / 深在设置里选。

## 后台 v0.1（2026-11-23，`code/server` 0.1.0）

**形态**：一个 Node 进程（`src/main.ts`），`/api/*` 是接口，其它路径给网页（`code/web/dist`）。网页和官网 / 试用是同一份打包，后台在 `index.html` 里注入 `window.OPERO_MODE='instance'`，网页就走真接口。Node 22.18+ 直接跑 `.ts`（类型擦除，不编译；只用可擦除的语法，`import` 带 `.ts` 后缀），`npm run typecheck` 做类型检查。

**两个系统用户**：`opero` 跑后台，读写 `/var/lib/opero`（数据库、`vault.key`、文件，0700）；`opero-ai` 跑 Claude Code / Codex（后台经 `sudo -n -u opero-ai -H --preserve-env=… bash -lc` 拉起），读不到数据目录。两人同在 `opero-work` 组，共享 `/srv/opero/work`（setgid 2770，两边 umask 007）。没设 `OPERO_AI_USER`（本机开发）时同一个用户跑，启动时会警告。

**存储**（`src/db.ts`，SQLite WAL）：`docs(coll,id,ts,data)` 放 JSON 文档（employees / sessions / servers / credentials / dataSources / savedQueries / triggers / kb / workspaces / devices），`messages(id,sid,ts,data)`、`audit`（只追加）、`runs`（每轮：员工、成没成、花费、token）、`secrets`（加密的值）、`auth_sessions`（存令牌的 sha256）、`push`（手机推送队列，留 7 天）、`kv`（owner、me、settings、ai、setupDone）。字段和网页 `types.ts` 一致，网页拿去就用。

**实时**：网页开一条 SSE `/api/events`，事件 `put / del`（某集合一项）、`msg / msgDel`、`audit`、`settings`、`me`、`usage`；断线重连后重新拉 `/api/bootstrap`。手机外壳长轮询 `/api/app/push`。

**执行器**（`src/runner.ts`）：一个员工同时最多一个进程。
- Claude Code：`-p --input-format stream-json --output-format stream-json --verbose --permission-mode (acceptEdits|default|plan) --max-turns --mcp-config <json> --permission-prompt-tool mcp__opero__approve --allowedTools mcp__opero --append-system-prompt <规矩> --add-dir <uploads> [--model] [--effort] [--resume]`。用户消息写进 stdin（图片作 base64 图片块）；每来一个 `result` 待处理数减一，减到 0 关 stdin，进程退出。
- Codex：`exec -c mcp_servers.opero.* [--image] --json --skip-git-repo-check -C <目录> (--dangerously-bypass-approvals-and-sandbox | --sandbox workspace-write | read-only) [-m] [resume <id>] -`，提示词走 stdin；新会话把规矩放在提示词前面。
- 规矩（系统提示）= 员工名字 + 职责 + 人设 + 「我的习惯」 + Opero 工具用法 + 工作目录。审核方式映射：auto → acceptEdits + 审核工具除危险命令都放行；edits → 改文件和只读命令放行、其它出卡片；ask → 只读工具外都出卡片；plan → 只读。
- 工作目录：员工选了项目就是 `work/ws/<名字>`，否则 `work/emp/<id>`。

**MCP**（`src/mcp.ts` 独立脚本，不 import 后台）：stdio JSON-RPC；`tools/list` → `GET /api/mcp/tools`，`tools/call` → `POST /api/mcp/call`，没马上好的（等你点卡片）返回 job，脚本再 `GET /api/mcp/wait/<job>` 长轮询（每次 20 秒）。认证 = 这一轮的随机令牌，只认本机直连（带 X-Forwarded-For 的拒）。工具实现在 `src/tools.ts`。

**等你决定的卡片**：工具发一张 `confirm` / `ask` 卡片（`data.pending = true`），`runner.waitCard` 等最多 30 分钟；网页点按钮 → `POST /api/messages/<id>/action`（`style: danger` 的按钮要 5 分钟内验证过本人）→ 放行。这一轮结束 / 停止 / 后台重启，没点的卡片标成失效。AI 用 `send_card` 发的普通卡片按钮点了，会变成一句话发给员工。

**安全**：cookie `opero_sid`（HttpOnly、SameSite=Lax、HTTPS 下 Secure）；改东西的请求要带 `X-Opero: 1`（防跨站）；登录 / 验证一分钟 8 次失败限流；SSH 主机指纹首次记下；执行器输出、命令结果里出现的密钥值替换成 ••••。

**接口一览**（`src/api.ts`）：`/api/bootstrap`、`/api/auth/{setup,login,logout,verify,password}`、`/api/events`、`/api/me`、`/api/settings`、`/api/ai`（执行器状态、Key、测试）、`/api/setup/{employees,done}`、`/api/employees`、`/api/sessions/:id/{messages,files,read,stop,new-topic}`、`/api/messages/:id/action`、`/api/uploads/:emp/:file`、`/api/files/:id`、`/api/servers[/:id/{check,exec}]`、`/api/credentials[/:id/reveal]`、`/api/data-sources[/:id/{schema,query}]`、`/api/saved-queries`、`/api/triggers[/:id/run]`、`/hook/:token`、`/api/kb`、`/api/workspaces[/:id/refresh]`、`/api/app/*`（外壳）、`/api/mcp/*`。

**指纹（server 0.6.0，`src/keys.ts` + `agent.ts`）**：在「令牌换密钥、后台只存 hash」的基础上再进一步。
- Agent：`/var/lib/opero-agent/id_ed25519.pem`（0600），指纹 = SSH 写法 `SHA256:base64(sha256(公钥 32 字节))`。每个请求带 `X-Opero-Agent-Pub`（公钥）`X-Opero-Ts` `X-Opero-Sig`（签 `方法\n路径\n时间\nsha256(请求体)`），Opero 验签、时间差 ≤ 5 分钟，按 `servers.agentFp` 认；不认识的建一条 `via = pending`（「等你接受」），接受 → `agent`，拒绝 → `rejected`；被移除的（`ssh` 但指纹还在）一律拒。带令牌注册时也要用公钥签名，马上就是 `agent`。旧版用 Bearer 密钥的照样认。
- Opero：`数据目录/opero_ed25519.pem`；`/api/agent/poll` 回 `{tasks, ts, server: 公钥, sig: 签(ts\ntasks)}`。Agent 第一次见到就钉住（`agent.json` 的 `serverPub`），之后不是这个公钥签的、签名不对、时间太旧的活一律不执行；`OPERO_TRUST_SERVER=<指纹>` 改认另一套。
- 换地址：Agent 的 `OPERO_SERVER` 变了只改连接地址、不重新注册；`POST /api/agents/move {url}` 给在线的 Agent 派 `move`（改 agent.env、重启自己）；命令行 `sudo opero agent-url <地址> [指纹]`、`opero fingerprint`。

**AI 网络出口（server 0.5.0，`src/tunnel.ts` + `agent.ts` 里的隧道）**：`ai.claudeEgress / codexEgress` = ''（直连）/ `local`（经 Opero 这台）/ 服务器编号（经那台 Agent）。干活那台本机有个只听 127.0.0.1 的 CONNECT 代理（Opero 这台由后台开在 `端口+1`，别的服务器由 Agent 开在 18089，口令随机，Agent 心跳报 `proxy:{port,token}`）；执行器拿到 `HTTPS_PROXY=http://<出口>:<口令>@127.0.0.1:<端口>`（`runner.egressEnv`，出口就是干活那台时不设）。代理收到 CONNECT → 开隧道：干活那台是 Agent 时报 `tup` 事件，Opero 给出口 Agent 派 `tconn`，出口连上回 `topen`，之后双方的字节走 `tdata`（base64，Agent→Opero 走 events、Opero→Agent 走长轮询的活），`tclose` 关。出口只许 443 + 名单里的域名（anthropic / claude / openai / chatgpt / 安装源），连之前查解析结果不是内网 / 本机 / 云元数据。Agent 掉线时经它的隧道都断。`POST /api/ai/egress-test` 在干活那台经出口 curl 一下 AI 接口。

**排队（server 0.4.0，`src/queue.ts`）**：员工在干活时的话：`POST /api/sessions/:id/messages {text, files:[{id,w,h}], mode}`，mode = queue 或插不进去（`runner.canInterject` 为假：Codex / 输入通道关了）就进队，否则插话 / 直接派活。附件先 `POST /api/sessions/:id/files` 传到员工目录 `uploads/`（还没发，`DELETE /api/sessions/:id/files/:file` 撤回），发的时候按文件名带上；队列项 `{id, emp, sid, text, files:[QAtt], at, source}` 存 docs coll `queue`、SSE 推送，最多 20 条。轮到时先把你的话和附件放进聊天再派活（排队时不进聊天，免得顺序乱）。runner 的 `setHooks({busy, idle})`：插不进去的（包括触发器、转派）进队；一轮结束且不是你停的 → `drain` 发下一条；停了就等 `POST /api/sessions/:id/queue/run`。`DELETE /api/queue/:id` 连附件一起删。排队时文字和图片 / 文件一起走，不会「排队把文字发了、图片丢了」。

**开工准备（server 0.24.3）**：派活后到执行器起来之前（准备记忆 / 拉项目代码 / 拉参考项目 / 准备环境 / 启动执行器），每一步都写在状态上；6 分钟还没起来就放弃这一轮（状态清掉、聊天里说卡在哪一步、这期间插的话进排队）；这时按「停止」立刻放下。远程命令（`agents.exec`、`runAiOn`）超时杀掉后最多再等 5 秒「已退出」，等不到也按超时返回——以前 Agent 那边连不上时会一直等，员工就一直挂在「在想…」。

**插话（Claude Code，server 0.24.2）**：干活时的话直接写进 stdin（stream-json），`pending` 记还没被读进去的条数。执行器支持 `--replay-user-messages` 时（看 `claude --help`），每读进一句会回显一条 `{type:'user', isReplay:true}`，按回显减；老版本按「一轮结束」（`result`）减。一轮结束 `pending = 0` 就关 stdin 收尾；不为 0 显示「在看你插的话…」，等新一轮——新一轮会立刻有 `system init` / 回复 / 回显。10 秒内没有这些，说明插的话已经并进刚才那一轮（Claude Code 会把干活中途来的话直接塞进当前这一轮），也收尾，不会一直挂着。

**编译和发布 v2（server 0.10.0 + web 0.23.0）：照云效那套**
- **编译组件（server 0.25.0）**：一个项目可以有好几个编译组件 `Workspace.builds: BuildComp[]`（`BuildComp = BuildCfg + { id, name }`，比如「网页」「安卓」「后台」），各自的模板、在哪编、流水线、试编译；发布目标 `Deploy.build` 选发哪个（组件编号；`'none'` = 不编译只跑部署命令；不填 = 项目只有一个组件时就是它，有好几个时必须选）。流水线按「项目 + 组件」区分：云效流水线名 `Opero · 项目 · 组件`、产物 `opero-<项目>-<组件>`；GitHub 工作流 `opero-build-<组件>.yml`；GitLab 一个 `.opero/gitlab-ci.yml` 里每个组件一个任务 `opero-build-<组件>`，触发时带 `OPERO_COMPONENT` 只跑那个；Jenkins 任务 `opero-<项目>-<组件>`（编号 `main` 的组件不带后缀）。试编译按组件各记各的、不同组件能一起编。接口：`PUT /api/workspaces/:id {builds: [...]}` 整个列表；`POST /api/workspaces/:id/builds/:bid/generate`、`POST|GET …/builds/:bid/try`、`GET …/builds/:bid/script`。员工工具 `build_info / build_set / build_generate / build_try / build_status` 都带 `component`（`build_set` 给新名字 = 新加，`remove: true` = 删），`release_target_set` 带 `build`。以前的单份 `buildCfg` 启动时转成编号 `main` 的组件（`migrateBuilds`）。
- 每个组件的编译设置（`src/build.ts`）：模板 node / go / android / spring / custom（脚本照以前云效模板：国内镜像装环境、产物放 out/、最后写 `SHA256SUMS / VERSION / COMMIT`；node / go 的包带 `deploy.sh`，android 出 `*-unsigned.apk`）；在哪编：
  - 云效：令牌（个人访问令牌，凭证）+ 组织（默认 Codeup 地址里的）；「生成流水线」用 Codeup 服务连接建 / 改 YAML（`公共集群 public/cn-beijing`、alinux3，可换构建镜像、上传产物 `opero-<项目>`），记下流水线编号；跑：带分支 `runningBranchs`，每 15 秒查一次，成功后拿 `dynamic_output.*.ARTIFACT_URL` 下载，失败带出失败那步日志里的错误行。
  - GitHub Actions：「生成流水线」用项目的令牌把 `.github/workflows/opero-build-<组件>.yml` 提交进仓库（`workflow_dispatch`，`actions/cache`，`upload-artifact out/`）；跑：dispatch → 找到这次运行 → 等完成 → 下载产物 zip（自己写的最小 zip 解压）。
  - 自己的服务器：在那台 `<工作根>/builds/<项目>/<发布>/src` 拉那个提交，跑同一个脚本，out/ 打 tgz 经 Agent `push` 回 Opero。
  - GitLab CI：仓库里 `.opero/gitlab-ci.yml`（每个走 GitLab 的组件一个任务），根 `.gitlab-ci.yml` include 它；见 `docs/规范/打包工具.md`。
- 发布（`src/releases.ts` 重写）：编译 → 产物下到 Opero（`数据目录/releases/<发布>/`，600 MB 以内）→ 按 `SHA256SUMS` 逐个核对 → 挑要发的文件（组件的 `file`，默认 *.tgz / *.apk / bundle.tgz）→ 发到环境的每台（Agent `pull`，带 sha256；派活本身带 Opero 签名）→ 解到 `<工作根>/releases/<项目>/<发布>/pkg` → 签名（apk / aab，可选，在那台用 apksigner / jarsigner）→ 部署：包里有 `deploy.sh`（或环境设的脚本名）就 `bash <脚本> <包目录> <发布编号>`，环境变量 `OPERO_DIR = KL_DIR = 部署目录`、`OPERO_PKG = KL_PKG`、`OPERO_VERSION`、`OPERO_RELEASE = KL_DEPLOY`（以前给云效写的部署脚本能直接用）；没有脚本跑环境的部署命令；都没有就把包复制进部署目录 → 检查。没设编译：每台在部署目录跑部署命令（`OPERO_REF`），回滚 = 用那个提交再跑一次。
- 发布环境 `Deploy`：`env`（这是哪个环境：生产 / 预发 / 测试 / 开发或自己起的标签，不填 = 跟发到的服务器的环境标签；server 0.25.9）、`build`（发哪个编译组件）、`servers[]`（多台）、`dir`（部署目录，每台都要在「目录」里登记成能部署，不然不让发）、`script`、`command`、`sign`、`health`、`keep`、`ai`、`autoRollback`。算不算生产看 `env.deployProtected`：`env` 像生产（`PROD_RE`），或者发到的服务器里有受保护的——只会多保护、不会少（服务器是生产的，环境标「开发」也照样按生产：发布验证本人、员工发前问、`release_publish` 的卡片标危险、新环境默认「发前问你」）。网页在发布页环境卡片上点「编辑」或项目设置里「改」都是同一个 `DeployForm`（最上面选环境、改名字）；员工用 `release_target_set {env}`。
- 服务器目录 `Server.dirs`（服务器详情「目录」，改要验证本人）：`read`（员工只读）/ `write`（员工能改）/ `deploy`（发布能部署进去）。保存后 Opero 经 Agent 以 root 用 ACL 给 AI 用户开权限（`setfacl -R -m u:opero-ai:rX|rwX` + 默认 ACL，上层目录给 x），去掉的收回；结果记在每项的 `ok / error`。系统目录只能只读。员工在那台干活时：只读的 `--add-dir` 进来、改文件被 `approve` 拦；能改的 `--add-dir` + Codex `writable_roots`；都写进规矩。Opero 这台自己不是 root，给的是要你自己跑的 setfacl 命令。

**登录和体验（server 0.9.0 + web 0.22.0 + android 0.2.0）**
- 通行密钥（`src/mfa.ts`，`kv passkeys`，网页 `src/webauthn.ts`）：自己写的 CBOR / COSE 解析，只认 ES256 / RS256，`attestation: none`、`userVerification: required`；域名 = 浏览器 Origin 的主机名（HTTPS，localhost 例外），挑战 32 字节、5 分钟、一次性；签名计数要涨。能用来**登录**（`/api/auth/passkey/options` + `/login`，登进来就算验证过本人）和**验证本人**（`/passkey/verify`）。加 / 删要先验证本人。
- 两步验证：TOTP（SHA1、6 位、30 秒、±1 步、同一步不认第二次），密钥在保险箱（`mfa-totp`），开的时候先 `setup` 拿密钥（`otpauth://` 地址 + 原文），输对一个码才生效，给 10 个恢复码（只存 sha256）。开了以后密码登录回 `{mfa, ticket}`，`/api/auth/mfa {ticket, code}` 才发会话（票 5 分钟、错 5 次作废）；用恢复码登录会推送提醒。验证本人也能用动态码。关掉 / 换恢复码要验证本人 + 一个码。
- 说话转文字：App 里用手机自带的语音识别（外壳 `OperoNative.voice(lang)` → `RecognizerIntent`，不要录音权限，结果回 `__operoNative.onVoice`）；浏览器里用 Web Speech（Chrome / Edge / Safari）。聊天输入框旁边一个话筒，点一下说一句，文字接在输入框后面，不会直接发。
- 看日志：服务器详情「日志」：`GET /api/servers/:id/services`（在跑的 systemd 服务）、`GET /api/servers/:id/logs?service=|file=&lines=`（journalctl / tail，20～2000 行），网页里按关键字过滤、错误标红、警告标黄，能每 5 秒刷新。

**发布 / 合并请求 / 签名 / DNS（server 0.9.0 + web 0.22.0）**
- 发布（`src/releases.ts`，coll `releases`，网页 store 里叫 `liveReleases`）：发布目标 = `Workspace.deploys[]`：`server` + `command`，可选 `build {server, command}`、`sign`（签名证书凭证）、`health`（地址）、`keep`（默认 5）、`ai`（auto / ask / off，默认 ask）、`autoRollback`（默认开）。一次发布：`git ls-remote` 拿远端最新提交 → 编译那台 `<工作根>/releases/<项目>/<发布>/src` 里 `git fetch --depth 1 <sha>` → 跑编译命令（`OPERO_SRC / OPERO_OUT / OPERO_REF / OPERO_VERSION / OPERO_RELEASE`），`OUT` 不能空 → 签名 → 编译和部署不在同一台时打成 tgz 经 Opero 搬（Agent 新活 `push` / `pull`，`/api/agent/blob/:key`，key 一次性、限定哪台传 / 哪台拿、300 MB 以内、带 sha256）→ 部署命令（多 `OPERO_PREV_OUT`）→ 检查（目标那台 curl，10 次 × 6 秒，2xx / 3xx）。部署 / 检查失败且上一个成功版本的产物还在 → 用它重新部署（`rollback` 步骤）。成功后只留最近 keep 个版本的产物目录。一个目标同时只能发一个；Opero 重启时还在发的标失败。回滚：`POST /api/releases/:id/rollback`（用留着的产物，没了就按那个提交重编）。版本号 = `年月日.时分-提交前 7 位`。

- 签名（`releases.sign` / `signFile`）：凭证组「签名证书」的值是 JSON `{keystore: base64, storePass, alias, keyPass}`（网页上传 keystore 文件拼的）；在编译那台临时写 keystore（umask 077，用完删），密码只经环境变量（`apksigner --ks-pass env:` / `jarsigner -storepass:env`），输出抹掉。员工工具 `sign_package {path, cert}`：只签它工作目录里的 apk / aab，签好的放旁边 `*-signed.*`。要证书「允许员工用」。
- 合并请求（`src/prs.ts`）：员工 `workBranch`（档案「在自己的分支上改」= `opero/<名字>`）：开工前 `autogit.preSync` 切到这个分支（没有就从 `origin/<主分支>` 拉一个；工作区不干净不切）；没设的员工开工前切回主分支。`pr_create`（先推分支，再调 GitHub / GitLab / Gitee / Codeup 的接口，令牌用项目的仓库凭证）、`pr_status`；聊天里一张合并请求卡片，「刷新状态」现查（合并了 / 关了卡片就收起）。提过的记在 `kv prs`。
- DNS（`src/dns.ts`，coll `domains`）：登记域名 = 域名 + Cloudflare / 阿里云 + 「云账号」凭证（Cloudflare：值 = API 令牌；阿里云：用户名 = AccessKeyId、值 = AccessKeySecret，RPC 签名 v1）。员工 `dns`（能改哪些域名）。工具 `dns_list / dns_set（同主机记录 + 类型就改）/ dns_delete`，审核方式不是自动先确认，改前改后记操作记录。网页「域名」页能看记录、加改删（要验证本人）。类型 A / AAAA / CNAME / TXT / MX / NS / SRV / CAA；阿里云 TTL 只能 600 / 1800 / 3600 / 43200 / 86400。

**网络出口（server 0.31.0 + web 0.48.0）**：Opero 自己往外连的地址，按域名经某台 Agent 出去（主人在「应用 → 服务器和 Agent → 网络出口」设，员工用 `egress_manage`）。
- 规则存 kv `egressRules`，`egress.ruleFor(host)` 取最具体的（完全一样 > 后缀最长），`via: 'direct'` 是给子域名开例外。`parseTarget` 认网址、邮箱、host:port、`*.域名`。
- 走法：内部 HTTP CONNECT 代理（`startInternalProxy`，只听 127.0.0.1、随机端口、口令只在进程里，**不给执行器**；用户名 = 出口编号，`~lan` = 许连内网）→ `tunnel.openFromSocket` → 和 AI 出口同一套隧道（Agent 的 `tconn` 多了 `any`、`lan`：任意域名和端口，默认拒内网地址）。fetch：`installFetch` 用 undici 的全局 `Agent({ connect })`，有规则的先 `dialVia` 再在上面做 TLS（端到端，出口看不到内容），没规则的用默认连接器；imapflow / nodemailer 用 `proxyFor(host)` 当 `proxy`。Agent 要 `tunnel.ANY_MIN`（0.31.0）以上，旧的直接报「去升级 Agent」。
- 「最近连不上的」：直连时的网络错误（fetch 连接器、收件箱 IMAP、邮件提醒 SMTP）`noteFail` 记在内存（30 个），界面一键「换个出口」，能「忽略」。这些地方的报错用 `egress.hint()` 补一句去哪设；凭证测试的报错也提了。
- 不管：数据库（有 SSH 隧道）、Git 推拉（git 命令自己连）、员工跑的命令（执行器有自己的 AI 出口）。

**写实头像（web 0.46.0）**：`code/web/public/avatars/rl-f01–f20.jpg`、`rl-m01–m20.jpg`，256×256 JPG（每张 12 KB 左右），`PRESETS` 里的「写实」一组、排第一；`randomPreset(性别, set='写实')` 新员工默认从这套挑。通义万相 wan2.2-t2i-plus 出 1024×1024 原图（人物描述 `code/web/scripts/avatars-real.tsv`：年龄 21–30、发型 / 穿着 / 浅色背景各不同，女生男生各 14 个东亚 + 6 个其它人种），`avatars-real.py` 裁中间 72%、往上挪 7%（脸占圆形头像六成，32px 也认得出）再缩。AI 生成、不是真人，许可见 `public/avatars/README.md`。

**Codex 的 ChatGPT 订阅账号（server 0.25.8 + web 0.41.13）**：Codex 账号两种：API Key（凭证 `meta.authMode=api`，值是 Key，经 `OPENAI_API_KEY / CODEX_API_KEY` 交给 codex）和 ChatGPT 订阅（`meta.authMode=chatgpt`，值是 Codex 的 `auth.json` 全文，`meta.email / plan / gen`）。用户手册在 `docs/AI执行器接入.md`。
- 登录：`POST /api/ai/login {executor:'codex'}` → `executors.startCodexLogin`：以 AI 用户跑 `codex login --device-auth -c cli_auth_credentials_store=file`（`script` 给伪终端，不然不出提示），`CODEX_HOME=~/.opero/codex/<新账号 id>`；从输出认出 `https://auth.openai.com/codex/device` 和一次性码（`XXXX-XXXXX`），job 进 `waitDevice`（`url`、`userCode`）。退出码 0 → 读回 `auth.json` → `saveCodexAuth`。失败给三个常见原因（ChatGPT 没开「设备码登录」、码过期 / 登错账号、连不上 auth.openai.com）。设备码登录 OpenAI 标着 beta，个人账号要先在 ChatGPT 设置 → 安全里打开，工作区要管理员打开。
- 贴 auth.json：`POST /api/ai/accounts {executor:'codex', value:'{…}'}` 也走 `saveCodexAuth`。它从 `tokens.id_token` 解出邮箱和 `chatgpt_plan_type`（名字默认「ChatGPT Plus · 邮箱」）；同一个邮箱的订阅账号已经有了就更新那个（`gen+1`），不另加；只有 `OPENAI_API_KEY` 的 auth.json 拒掉、让贴 Key。
- 干活：`aiEnv('codex')` 用 `pickAccount('codex', emp)`（员工的 `codexAccount` → 默认 → 其它，到上限的往后排）。订阅账号不设 Key，设 `OPERO_CODEX_ACCT / OPERO_CODEX_AUTH / OPERO_CODEX_GEN`；`codexCmd()` 把 codex 包成 `bash -c CODEX_PREP codex …`：建 `~/.opero/codex/<id>`（0700）、那台的 `.opero-gen` 和保险箱的 `gen` 不一样才写 `auth.json`（0600，先写临时文件再换），`sessions` 链到 `~/.codex/sessions`（换账号也能 `resume` 原来的会话），清掉 `OPERO_CODEX_AUTH` 再 `exec`（进程号不变，员工跑的命令看不到这个变量）。打码用的秘密里加上 auth.json 里的几个令牌。
- 续期：Codex 用的时候自己续期令牌、写回它的 `auth.json`。每轮结束（`after`）、`/api/ai/test`、`oneShot` 之后 `syncCodexAuth` 读回来，和保险箱不一样就存回去、`gen+1`、把那台的 `.opero-gen` 对上；别的服务器下次起进程看到 `gen` 变了就拿新的。已知限制：同一个订阅账号同时在两台服务器上续期，有可能互相把对方的 refresh token 顶掉（那就重新登录一次）。
- 到上限：`limitHit` 对 Codex 也生效（`usage limit / try again in / 429…`），记 `claudeLimited[账号]`，后面的活先换别的 Codex 账号。登录失效（refresh 失败、401）时聊天里提示到第 3 步重新登录这个账号。去掉订阅账号时把 Opero 这台的 `~/.opero/codex/<id>` 一起删。
- 计费标记：订阅账号的一轮记 `sub`，API Key 记 `api`；没有账号（AI 用户自己在 `~/.codex` 登录过）也算 `sub`。

**国内的执行器：Qwen Code、CodeBuddy Code（server 0.25.7 + web 0.41.12）**：都走 Claude Code 那套 stream-json 驱动（`runner.ts` 里 `driverOf(exec) = 'claude'`，`exec = kindOf(emp.executor)` 是 `claude | codex | qwen | codebuddy`），能插话、续上会话。
- 安装：`executors.ts` 用 npm 装 `@qwen-code/qwen-code`（命令 `qwen`）/ `@tencent-ai/codebuddy-code`（命令 `codebuddy`），先国内镜像、再官方源；路径可用 `OPERO_QWEN_BIN` / `OPERO_CODEBUDDY_BIN` 改。Agent 心跳也报这两个的版本。
- 账号：存在 `kv ai` 的 `accounts[种类]`（凭证 id 列表）+ `defaults[种类]`（默认），用默认账号。接口同 Claude / Codex：`POST /api/ai/accounts {executor:'qwen'|'codebuddy', value, name?, baseUrl?, model?, region?}`、`PUT /api/ai/accounts/:id {isDefault, name, baseUrl, model, region}`。
- Qwen Code：`--input-format stream-json -o stream-json --auth-type openai`，环境变量 `OPENAI_API_KEY`（百炼按量 API Key；百炼 Coding Plan 条款不许自动化调用，别用）、`OPENAI_BASE_URL`（账号上的 `meta.baseUrl`，默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`）、`OPENAI_MODEL`（员工选的模型 → 账号上的 `meta.model` → `qwen3-coder-plus`）。审核方式 → `--approval-mode plan/default/auto-edit/yolo`；MCP 经 `--mcp-config`（opero 服务 `trust:true`、超时 1900 秒）；`--max-session-turns`、`--append-system-prompt`、`--add-dir`、`--resume`。
- CodeBuddy Code：参数和 Claude Code 几乎一样（`-p --output-format stream-json --input-format stream-json --verbose`、`--permission-mode`、`--max-turns`、`--mcp-config --strict-mcp-config`、`--allowedTools mcp__opero`、`--disallowedTools` 挡数据目录、`--model`、`--effort`（help 里有才加）、`--resume`）。环境变量 `CODEBUDDY_API_KEY`；账号 `meta.region` 不是 `intl` 时设 `CODEBUDDY_INTERNET_ENVIRONMENT=internal`（国内站 codebuddy.cn），`meta.baseUrl` → `CODEBUDDY_BASE_URL`。
- 两家都没有 `--permission-prompt-tool`：命令逐条检查（`approve`）只有 Claude Code 有，别的执行器的规矩写进提示词；不需要网络出口（国内直连）；用量按 API 计。`POST /api/ai/test` 对四种都用员工干活时同一套环境变量（`runner.aiEnv`）跑一句。
- Kimi Code 只有 ACP 驱动，等做 ACP 通用驱动时再接（见 `docs/调研-agent-CLI.md`）。

**接 AI 执行器（傻瓜式，server 0.2.0，`src/executors.ts` + 网页 `components/ExecutorSetup.tsx`）**：同一时间一个 job，网页每秒 `GET /api/ai/job` 问进度。
- 安装 `POST /api/ai/install {executor}`：以 AI 用户依次试官方脚本 `curl -fsSL https://claude.ai/install.sh | bash` → `npm install -g @anthropic-ai/claude-code --prefix ~/.local` → 同样走 npmmirror；Codex 用 npm。装完跑 `--version` 确认。
- 订阅登录 `POST /api/ai/login`：以 AI 用户跑 `script -qfec "stty cols 500 rows 60; exec claude setup-token" /dev/null`（伪终端），用小终端模拟器还原屏幕，找登录网址（OSC 8 超链接或屏幕上的 oauth 网址）→ job.state = waitCode；网页 `POST /api/ai/login/code {code}` 把授权码写进去（先码、400ms 后回车）；屏幕出现 `sk-ant-oat…` 令牌后杀掉界面，用 `CLAUDE_CODE_OAUTH_TOKEN` 跑一次 `claude -p` 验证，通过才加密存进保险箱（`kv ai.claudeCred`）。令牌不落文件、不进日志。15 分钟超时；`POST /api/ai/job/cancel` 取消。授权码框里贴的是完整的 `sk-ant-oat…` 令牌时直接验证保存；界面提示「码不完整」时回到 waitCode 并把原因放进 job.message。已有令牌也可以 `POST /api/ai/login/token {token, host}` 直接验证保存（不起 setup-token）。

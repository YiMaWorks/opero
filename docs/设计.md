# opero 设计

> 还没开发。需求原文在 `需求.md`（以它为准），下面是从需求里摘出的设计骨架，开发时再细化；标「待确认」的要确认。

## 一句话
以聊天为入口、由 AI 员工驱动的开源后台：「员工 → 聊天 → 员工去做」，不是「菜单 → 页面 → 按钮」。从旧后台（KidLock 超级后台）**重新设计**，不沿用旧表。

## 核心概念
员工 · 工作空间 · 会话 · 授权 · 资源 · 凭证。员工、资源、凭证互相独立，只靠授权（`grant`）连起来。（详见 `需求.md` 第 1 节）

## 模块（`需求.md` 第 12 节）
- 入口：网页（聊天，三栏）· 桌面壳（同一套网页）· 安卓 App（Compose 外壳 + WebView 表单）· 员工对外接口
- 后台：账号 · 员工 · 资源 · 凭证 · 授权与申请 · **判定** · 会话与卡片 · 派活编排 · 文件 · 通知 · 审计 · 工具注册 · 插件加载
- Agent（Go，必装）：主动连出、执行 / 只读查询、沙箱跑执行器（Claude Code / Codex）、资源上限、监控、自动升级
- 存储：MySQL · 文件目录 · 员工的 git 仓库

## 技术栈（需求建议，待确认）
Node + Fastify + React + MySQL + Go Agent；桌面壳 Tauri 或 Electron（未定）；安卓 Compose。

## 代码目录（待确认）
需求建议 `server/ web/ desktop/ agent/ app-android/ plugins/ sql/ docs/`；本仓库规矩是代码都放 `code/`，所以打算用 `code/server`、`code/web`、`code/desktop`、`code/agent`、`code/app-android`、`code/plugins`、`code/sql`，文档仍在根下 `docs/`。

## 关键设计决定（来自需求）
1. **唯一判定函数**：`判定(谁, 通过哪个员工, 动作, 资源) → 允许 / 要确认 / 要申请 / 拒绝(原因)`；AI 调工具、表单提交、底部菜单、面板按钮显隐全走它；二开在这里挂规则。
2. **工具自声明**：所属员工、动作名、风险级别（读 / 写 / 危险）、资源类型。
3. **权限两标签**：管理员 / 普通用户；员工用资源靠长期授权或单次申请；自动审核开关（危险操作永远不能自动）。
4. **环境只做生产保护**，不参与权限；改生产先出确认卡片 + 验证本人（30 分钟有效）。
5. **AI 永远拿不到凭证明文**，只拿编号；防线写在代码里不靠提示词。
6. **表单 = MCP Apps**（`ui://插件/表单`），沙箱运行，经宿主转工具调用；通用「提问」工具兜底。
7. **插件优先、不改内核**；后台开发员工改自己：先预览再上线、健康检查不过自动回滚、不能改授权 / 审计 / 验证本人代码。
8. 审计一条不落。

## 前端结构（2026-11-22，`code/web` 0.2 定下）
- **数据仓库 `store.ts`**：页面只从这里读（`useStore(选择器)`）、只调这里的动作（发消息、改卡片、置顶、存员工、批申请、存凭证……）。接后台时：初始数据 → 调接口；消息 / 卡片更新 → 服务器推送写进 store；动作 → 调接口。页面不改。
- **页面 = 路由 + 导航**：`pages/index.tsx` 页面名 → 组件；每个页签一摞页面（进下一页 / 返回）；聊天右侧面板也是一摞页面（员工底部菜单打开的就是这些页面）。页面只拿到 `Nav`（push / back / close / openChat），不关心自己在页签里还是面板里。
- **返回**：每打开一层（聊天、页面、面板、弹层、验证本人）记一步浏览器历史；侧滑 / 返回键只关最上面一层。
- **卡片按钮 = 工具调用**：现在在 `App.tsx` 的 `onCardAction` 里按类型模拟；接网关后统一改成「调工具 → 结果写回卡片」。
- **危险操作统一走 `requireVerify`**（验证本人弹层），审计统一走 `audit()`。
- **主题**：`styles.css` 颜色全是变量，`:root[data-theme=dark]` 换一套；跟随系统 / 浅 / 深在设置里选。

## 后台 v0.1（2026-11-23，`code/server` 0.1.0）

**形态**：一个 Node 进程（`src/main.ts`），`/api/*` 是接口，其它路径给网页（`code/web/dist`）。网页和官网 / 试用是同一份打包，后台在 `index.html` 里注入 `window.OPERO_MODE='instance'`，网页就走真接口。Node 22.18+ 直接跑 `.ts`（类型擦除，不编译；只用可擦除的语法，`import` 带 `.ts` 后缀），`npm run typecheck` 做类型检查。

**两个系统用户**：`opero` 跑后台，读写 `/var/lib/opero`（数据库、`vault.key`、文件，0700）；`opero-ai` 跑 Claude Code / Codex（后台经 `sudo -n -u opero-ai -H --preserve-env=… bash -lc` 拉起），读不到数据目录。两人同在 `opero-work` 组，共享 `/srv/opero/work`（setgid 2770，两边 umask 007）。没设 `OPERO_AI_USER`（本机开发）时同一个用户跑，启动时会警告。

**存储**（`src/db.ts`，SQLite WAL）：`docs(coll,id,ts,data)` 放 JSON 文档（employees / sessions / servers / credentials / dataSources / savedQueries / triggers / kb / workspaces / devices），`messages(id,sid,ts,data)`、`audit`（只追加）、`runs`（每轮：员工、成没成、花费、token）、`secrets`（加密的值）、`auth_sessions`（存令牌的 sha256）、`push`（手机推送队列，留 7 天）、`kv`（owner、me、settings、ai、setupDone）。字段和网页 `types.ts` 一致，网页拿去就用。

**实时**：网页开一条 SSE `/api/events`，事件 `put / del`（某集合一项）、`msg / msgDel`、`audit`、`settings`、`me`、`usage`；断线重连后重新拉 `/api/bootstrap`。手机外壳长轮询 `/api/app/push`。

**执行器**（`src/runner.ts`）：一个员工同时最多一个进程。
- Claude Code：`-p --input-format stream-json --output-format stream-json --verbose --permission-mode (acceptEdits|default|plan) --max-turns --mcp-config <json> --permission-prompt-tool mcp__opero__approve --allowedTools mcp__opero --append-system-prompt <规矩> --add-dir <uploads> [--model] [--effort] [--resume]`。用户消息写进 stdin（图片作 base64 图片块）；每来一个 `result` 待处理数减一，减到 0 关 stdin，进程退出。
- Codex：`exec -c mcp_servers.opero.* [--image] --json --skip-git-repo-check -C <目录> (--dangerously-bypass-approvals-and-sandbox | --sandbox workspace-write | read-only) [-m] [resume <id>] -`，提示词走 stdin；新会话把规矩放在提示词前面。
- 规矩（系统提示）= 员工名字 + 职责 + 人设 + 「我的习惯」 + Opero 工具用法 + 工作目录。审核方式映射：auto → acceptEdits + 审核工具除危险命令都放行；edits → 改文件和只读命令放行、其它出卡片；ask → 只读工具外都出卡片；plan → 只读。
- 工作目录：员工选了工作空间就是 `work/ws/<名字>`，否则 `work/emp/<id>`。

**MCP**（`src/mcp.ts` 独立脚本，不 import 后台）：stdio JSON-RPC；`tools/list` → `GET /api/mcp/tools`，`tools/call` → `POST /api/mcp/call`，没马上好的（等你点卡片）返回 job，脚本再 `GET /api/mcp/wait/<job>` 长轮询（每次 20 秒）。认证 = 这一轮的随机令牌，只认本机直连（带 X-Forwarded-For 的拒）。工具实现在 `src/tools.ts`。

**等你决定的卡片**：工具发一张 `confirm` / `ask` 卡片（`data.pending = true`），`runner.waitCard` 等最多 30 分钟；网页点按钮 → `POST /api/messages/<id>/action`（`style: danger` 的按钮要 5 分钟内验证过本人）→ 放行。这一轮结束 / 停止 / 后台重启，没点的卡片标成失效。AI 用 `send_card` 发的普通卡片按钮点了，会变成一句话发给员工。

**安全**：cookie `opero_sid`（HttpOnly、SameSite=Lax、HTTPS 下 Secure）；改东西的请求要带 `X-Opero: 1`（防跨站）；登录 / 验证一分钟 8 次失败限流；SSH 主机指纹首次记下；执行器输出、命令结果里出现的密钥值替换成 ••••。

**接口一览**（`src/api.ts`）：`/api/bootstrap`、`/api/auth/{setup,login,logout,verify,password}`、`/api/events`、`/api/me`、`/api/settings`、`/api/ai`（执行器状态、Key、测试）、`/api/setup/{employees,done}`、`/api/employees`、`/api/sessions/:id/{messages,files,read,stop,new-topic}`、`/api/messages/:id/action`、`/api/uploads/:emp/:file`、`/api/files/:id`、`/api/servers[/:id/{check,exec}]`、`/api/credentials[/:id/reveal]`、`/api/data-sources[/:id/{schema,query}]`、`/api/saved-queries`、`/api/triggers[/:id/run]`、`/hook/:token`、`/api/kb`、`/api/workspaces[/:id/refresh]`、`/api/app/*`（外壳）、`/api/mcp/*`。

**接 AI 执行器（傻瓜式，server 0.2.0，`src/executors.ts` + 网页 `components/ExecutorSetup.tsx`）**：同一时间一个 job，网页每秒 `GET /api/ai/job` 问进度。
- 安装 `POST /api/ai/install {executor}`：以 AI 用户依次试官方脚本 `curl -fsSL https://claude.ai/install.sh | bash` → `npm install -g @anthropic-ai/claude-code --prefix ~/.local` → 同样走 npmmirror；Codex 用 npm。装完跑 `--version` 确认。
- 订阅登录 `POST /api/ai/login`：以 AI 用户跑 `script -qfec "stty cols 500 rows 60; exec claude setup-token" /dev/null`（伪终端），用小终端模拟器还原屏幕，找登录网址（OSC 8 超链接或屏幕上的 oauth 网址）→ job.state = waitCode；网页 `POST /api/ai/login/code {code}` 把授权码写进去（先码、400ms 后回车）；屏幕出现 `sk-ant-oat…` 令牌后杀掉界面，用 `CLAUDE_CODE_OAUTH_TOKEN` 跑一次 `claude -p` 验证，通过才加密存进保险箱（`kv ai.claudeCred`）。令牌不落文件、不进日志。15 分钟超时；`POST /api/ai/job/cancel` 取消。照 KidLock `agent/inv_cclogin.go`。
